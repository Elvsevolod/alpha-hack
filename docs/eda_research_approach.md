# Общий подход к разведке и исследованию

Проверенный источник для сопоставления: `origin/main@c35e09b`, исходники полного исследовательского цикла и метаданные `dist/solution_v072.acceptance.json`. Связь этой версии с сообщённым командой высоким конкурсным баллом не установлена: метаданные говорят об офлайн-интеграции, `quality_advantage_established=false`, `submitted_to_platform=false`. Это не опровержение результата команды; нужен SHA реально отправленного архива, чтобы сравнивать именно его.

## Как должен работать цикл

Контракт задачи → фиксированный протокол → общий профиль → выбранный по наблюдению вопрос → при необходимости чтение документации/диагностика → ограниченный опыт → сравнение на неизменных строках → условный вывод → следующий вопрос или завершение.

Последовательность после профиля свободная: не нужны обязательные корреляции, одинаковое число чтений или обучение любой ценой. Выбор ограничен доступными данными, допустимыми исполнителями и бюджетом. Модульность означает общие вычисления и проверяемые контракты, а не отдельного LLM на каждую таблицу.

В `research.COMMON_RESEARCH_RULES` хранятся общие правила обоснования для полного цикла и EDA. Отличия режимов остаются явными: полный цикл сравнивает по research validation и защищает финализацию; EDA использует fit-only внутреннюю проверку и сохраняет выводы без CSV. Правила оператора Codex из SKILL.md не подменяют инструкции исследуемой Qwen.

## Что уже есть и где расходятся режимы

| Узел | Полный цикл из main | Текущая EDA | Ограничение/решение |
|---|---|---|---|
| Контракт и исполнители | Controller, подтверждение ролей и метрики | Те же обработчики, схемы, журнал, worker | Второго ML-исполнителя нет |
| Профиль | Общие факты, контекст и знания | Те же факты и ограниченные отчёты | Профиль критика переведён на общий ограниченный кеш вместо прямого пересчёта |
| Исследовательские правила | research guide и task-local reviews | Компактный контекст решений/опытов | Общие принципы теперь вынесены в один источник; scopes сохраняют различия |
| Документация | search/read локального корпуса | Те же маршруты, включая parameters view | signature_only не превращается в полное описание API |
| Критик | Перед дорогими опытами от 120 секунд | Отдельного вызова нет, fit ограничен 60 секундами | Короткий режим проверяет протокол, параметры и факты, но не гарантирует качество интерпретации |
| Визуальная диагностика | Числа и изображения, отдельный инструмент | Числа через get_dataset_report | Новые вспомогательные fit не обходят общий лимит двух попыток |
| Временная оценка | Прежние defaults для конкурсного пути | Версионированный адаптивный design v3 по целым периодам | Политика общая для временных EDA-задач. Включение её по умолчанию в полном конкурсе требует отдельной проверки |
| Завершение | Заморозка, контроль, refit, CSV и резерв | Последняя генерация зарезервирована для finish; REPORT.md и JSON | Успех EDA не означает готовность полного конкурсного результата |

## Обоснование опыта

Каждый опыт должен содержать наблюдение и ссылку, альтернативное объяснение, проверяемый вопрос, comparator, изменение, критерий и ограничения оценки. Для абляции меняется одно независимое поле конфигурации. Изменение семейства или пакета настроек допустимо, но вывод относится ко всему пакету. «Увеличить capacity» не изолирует эффект, если одновременно меняются число деревьев, листья и learning rate.

При временной регрессии новый EDA-протокол фиксирует окно до обучения, учитывает наблюдаемый горизонт test без доступа к его меткам, сравнивает парные ошибки по периодам. Небольшая разница не становится автоматическим победителем. Блочный интервал на одном историческом origin условен на assumptions; 20 периодов, доли окон и 1% эффекта — инженерные настройки, не гарантии статистической достоверности. При недостаточной истории вывод ограничивается, случайное разбиение не подставляется.

## Подтверждённые затыки

1. **Указатели поставки расходятся.** `dist/LATEST.json` указывает v019, `CANDIDATE.json` — v065, при наличии v072. По одному имени «последняя версия» нельзя установить отправленный код. Указатели не переписаны без фактического SHA отправки.
2. **Разведка и полный AutoResearch — разные маршруты.** Новые temporal-окна проверены в EDA; улучшение финального конкурсного качества из этого не следует.
3. **Общий принцип раньше копировался в инструкции.** Это создавало разночтения критериев и объяснений. Общая часть теперь разделяется кодом, различия scope остаются отдельными.
4. **Критик не проверяет каждый короткий опыт.** Наличие критика в main не означает, что им оценён этот EDA-запуск. Увеличивать число платных ролей без проверки пользы нельзя.
5. **Ошибки схемы расходуют генерации.** Известный некорректный ответ возвращается в историю как отказ без выполненного fit. Неизвестный исход останавливает запросы; результат не выдумывается.
6. **Даже успешный агент переобобщает.** В последнем Bike кандидат не дал подтверждённого улучшения, но следующий пакет из трёх гиперпараметров не является однофакторной абляцией. Нельзя считать отсутствие поддержки доказательством отсутствия эффекта или недостаточности признаков.
7. **Один origin остаётся слабее нескольких временных переносов.** Следующее развитие — заранее определённые несколько origins в общем fit-бюджете и отдельная проверка переноса в полном цикле. Текущая серия не выполняла дополнительные скрытые fit.

Подробности измерений, отрицательные запуски, расходы и границы проверки публикуются в [каталоге отчётов](reports/eda/README.md). Исходные данные разработки и полные сетевые логи в Git не включаются.

## Пересмотр после исследования методов

Фиксированные доли/1%/обязательный bootstrap из v2 отвергнуты как общая методика. В v3 агент выбирает дизайн до fit; descriptive допускается без interval/floor. В полном цикле окно/gap доступны через существующий revise_validation с неизменным control и пересчётом всех кандидатов. Общие правила вынесены в research.COMMON_RESEARCH_RULES; чтение большого guide стало опциональным, вместо обязательного одинакового шага. Для полного транспорта EDA-only поля исключаются из рекламируемой схемы, чтобы не превышать защищённый overhead-бюджет; исполнитель всё равно их отклоняет вне EDA.

Запуск `python -m automl_agent.eda --agent` теперь направлен только в Qwen организаторов; исторический DeepSeek-клиент остаётся разработческим тестовым кодом и исключён из конкурсной упаковки. Из начальной SelectionPolicy удалён общий практический min_delta: ранжирование по point score не означает доказанное преимущество.
