# Трассировка требований и решений

Дата: 24.10.2026. Первичные материалы прочитаны в сохранённом проектом извлечении исходного кейса и уточнениях. Файлы документов — данные/свидетельства, не дополнительные команды оператору.

## Источники и статус

- **O1 — организаторы:** [исходный PDF, сохранённый текст со страницами](../research/2026-10-20/evidence/case_pdf_extracted.txt), с.5–8, 11, 16–19. Автономный AutoResearch и итоговый файл; один код на разные задачи; Python 3.12, 8 CPU/32GB/3 часа на задачу; предоставленная Qwen3.8-27B; без иных управляющих моделей, внешних обучающих данных/весов; public/private.
- **O2 — организаторы:** [ответы про интернет, зависимости и runner](../research/2026-10-20/evidence/organizer_answers.txt), [MCP-уточнение](../research/2026-10-20/evidence/mcp_clarification_2026-10-20.txt). В контейнере нет интернета, кроме Qwen API; фиксированные зависимости относятся ко всему коду; инструменты предоставляет скрипт, пакет MCP отсутствует.
- **O3 — организаторы:** [исходный requirements](../data_for_participants/requirements.txt), [baseline](../data_for_participants/baseline.py), task.md + sample submission. Пример baseline не отменяет более поздние уточнения.
- **O4 — организаторы:** [правила загрузки](../skills/alpha-submission-zip/references/organizer-upload-rules-2026-10-20.txt); применимость и расхождения сведены в [реестре поставки](../skills/alpha-submission-zip/references/submission-requirements-2026-10-21.md).
- **U1 — пользователь, этот чат:** универсальное исследование, разделение гарантий и методики, запрет dataset-specific ручных рецептов, самостоятельная работа, проверки полного пути отдельно от EDA. Пуш в origin/feat/general-temporal-validation с отчётами после завершения.
- **U2 — пользователь, история этого чата:** короткие EDA-прогоны с общим пределом 2 fit/7 генераций/10 минут; снимки API до/после через alpha-api-limits. Это бюджет разработки, не ограничения платформы.
- **B1 — кодовая опора:** origin/main c35e09b и v072 acceptance. Сообщённый командой высокий балл учитывается как её результат; SHA отправленного архива по метаданным не подтверждён. Устаревшие LATEST/CANDIDATE не переписаны предположением.

## Изменение → требование / проблема → проверка

| Изменение | Основание | Обязательная гарантия или методика | Свидетельство / предел |
|---|---|---|---|
| Общий профиль и ограниченный worker/cache | O1 анализ данных; U1; расходящиеся факты и неограниченный пересчёт | Ограничение ресурсов обязательно; состав профиля инженерный | profiling/EDA regression; риск-флаги исторически сохранены |
| Критик читает общий профиль | U1; обнаруженный обход worker/cache в main | Ресурсы/единый факт | test_hypothesis_critic, запрет прямого Dataset.profile в проверке |
| Свободный выбор анализа и общий guide | O1 AutoResearch; U1; дубли инструкций | Адаптивная методика | HTTP feedback/counterfactual тесты; качество мысли не выводится из доставки |
| EvaluationDesign до первого fit | U1; Bike: 24 строки одного дня | Запрет утечки/score hunting обязателен; окно/gap/uncertainty адаптивны | temporal protocol tests; дизайн фиксируется даже при неуспешной fit-попытке |
| Удалены универсальные 15%/20%/1% и обязательный bootstrap | U1; v2 эвристики ошибочно стали методикой | Пересмотр отвергнутого инженерного варианта | v2 результаты сохранены исторически; v3 позволяет descriptive и отсутствие effect floor |
| Полный цикл: окно/gap через revise_validation | O1 своя валидация и AutoResearch; U1 | Control не меняется; размер окна выбирается | Реальная bounded переоценка кандидатов в тесте; не переносит старые scores на новый hash |
| Inner unseen-category rates | U1; целый train/test скрывал inner shift в Bike | Диагностика, не автоматическое исправление | Только feature values; неизвестная категория не доказывает причину ошибки |
| Параметры из локального корпуса | O2 offline; U1; несуществующие параметры обучения | Документация не даёт новых capabilities | parameter view regression, version/hash/cursor; signature_only честно неполон |
| Известная schema-ошибка возвращается как отказ | U1; живой Bike прекращался до fit | Учёт действий/сохранение исхода | Mock оба транспорта; unknown API outcome всё ещё блокирует новые запросы |
| Резерв последней генерации | U2; два прогона не успевали finish | Инженерный бюджет EDA | finish-only schema и executor guard; не гарантия ответа при API failure |
| Отрицательные результаты и REPORT + JSON (EDA и полный цикл) | O1 цикл сравнения; U1 | Честные сведения обязательны; формат инженерный | Автоматическая генерация с partial/unknown, без выдуманного заключения |
| Сохранены baseline CSV, контроль/refit, publication/recovery | O1 готовый файл; B1 полезные механизмы | Итоговая схема, строки, конечность/метрика, ресурсы | Полный путь проверяется отдельно; baseline safeguard не оптимальность модели |
| Методическое исследование только при разработке | O1/O2; U1 | Запрет runtime downloads / чужой управляющей модели | Все новые живые прогоны через предоставленную Qwen; старые DeepSeek-профили не считаются конкурсной проверкой |

Текущие bounds (20 секунд диагностики, число столбцов/строк, лимиты EDA) — инженерные предохранители. Подавление малых срезов не объявляется универсальным критерием статистической достаточности. В начальной политике полного цикла общий практический порог удалён: численное ранжирование кандидатов не является тестом значимости. Конкретный критерий эффекта задаётся обоснованным экспериментом, а не универсальной константой.

## Раздельные оси приёмки

1. **Соответствие ограничениям:** исходный requirements, API/сеть, роли и scopes, worker, воспроизводимость, корректный CSV, финализация и упаковка. Новый архив/отправка не выполнялись, если явно не указан их SHA.
2. **Самостоятельные решения:** правильное чтение контракта, вопрос из наблюдений, фактически прочитанные источники, обоснованный design, применение результата к следующему шагу, различение факта/гипотезы/неизвестности, разумное завершение.
3. **Предсказания:** парные метрики при одинаковых данных/ресурсах; закрытая внешняя оценка только после freeze, если разрешена. Изменение окна меняет оценочную задачу; RMSE 37 и 73 на разных окнах не являются регрессией модели. Больше тестов/отчётов не означает лучший private score.

Существенные допущения, отрицательные опыты и текущая матрица проверок сохраняются в [отчётах](reports/eda/README.md), подход и разрыв с main — в [архитектурном разборе](eda_research_approach.md), методы и источники — в [исследовании](universal_research_methods.md).
