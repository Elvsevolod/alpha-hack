# Исследование методов для двух примеров хакатона

Дата: 25 октября 2026. Источники изучались при разработке. Конкурсному контейнеру интернет, внешние данные, готовые веса и скачивание пакетов не добавлялись. Опубликованные результаты не превращались в обучающие метки: использованы только CSV организаторов. Это исследование reference-решений; самостоятельность управляющей модели здесь не проверяется.

## Матрица «проблема → подход → проверка»

| Наблюдаемая проблема | Проверяемый подход | Ограничение и цена |
|---|---|---|
| Регрессионный рецепт выбрали по одному году | Два forward-origin сравнения: 1–2 → 3 и 1–3 → 4; среднее двух RMSE | Два обучения на рецепт; два года не устанавливают устойчивость к любому переносу |
| Пропущен рейтинг ENERGY STAR | Extra Trees прогнозирует только рейтинг по характеристикам здания; отсутствующие рейтинги заполняются, индикатор сохраняется | Дополнительный fit в каждой части, без `site_eui` и без validation-значений при обучении imputer; может усиливать ошибки |
| Модель может плохо представлять нелинейные зависимости | Категориальные комбинации, log площади, альтернативная координата рейтинга, сезонные признаки | Статические функции без меток; это пакет признаков, его общий результат не доказывает пользу каждого элемента |
| Недостаточное разнообразие моделей | Регуляризованные XGBoost, Extra Trees/RF и MLP с подготовкой данных | Бустинг обычно дешевле; forest хранит много деревьев; MLP требует нормализации и имеет ограничение числа эпох |
| Классификация оптимизировала log loss при оценке Macro F1 | LightGBM с early stopping по Macro F1 после фиксированной частотной поправки | Не полная совместная оптимизация дерева и всех правил решения; проверяется как кандидат |
| Поправка по частотам недостаточно описывает ошибки классов | Сдвиги `log(p_k)` в пределах ±1, с ослаблением по support | До двух проходов координатного поиска; обучение границ только на calibration, оценка на selection |
| Совпадающие входные строки и редкие классы завышают уверенность | Целые группы одинаковых признаков в разных частях, явный support | Группы не являются подтверждёнными независимыми сессиями; промежуточные ошибки коррелированы |

Для коррекции границ используется инженерное ослабление `support / (support + 50)`; 50 — выбранный параметр этой серии, а не статистическая гарантия. Публикации не устанавливают такой константы. Никаких универсальных порогов улучшения, обязательного bootstrap или одинаковых временных окон из этого не следует.

## Протокол новой серии

Кандидаты и разбиения записываются до обучения. Семейства используют существующую фабрику `make_estimator`; исследовательский worker расширен подготовкой матрицы и сохранением преобразований, а не вторым комплектом реализаций алгоритмов. Все новые утилиты находятся в `tools/`, вне конкурсного runtime.

**Регрессия.** Девять рецептов, по два обучения: два прежних компонента, CatBoost с признаками, его вариант с imputation, регуляризованный LightGBM, два XGBoost, Extra Trees и MLP. Отбор по среднему RMSE двух следующих периодов. Дополнительно проверяется ограниченная сетка смесей лучших одиночных рецептов и прежней пары. Число деревьев для refit — медиана двух результатов early stopping; существенный разброс по годам фиксируется как ограничение этого инженерного решения.

**Классификация.** Прежние fit/tune/control сохраняются. Tune делится на две части по целым группам признаков. В первом направлении одна часть используется для early stopping и настройки offsets, другая — для оценки; во втором роли меняются. Основной fit не включает ни одну из них. Проверяются восемь рецептов и ограниченные смеси. Это взаимодополняющие разбиения calibration/selection, **не полноценный nested cross-validation и не классический OOF по всему train**. Смещение, вызванное перебором рецептов, остаётся; итоговый средний selection score нельзя считать независимой оценкой качества.

Offsets усредняются между двумя calibration-настройками и замораживаются. Число итераций, состав смеси, веса и правило решения сохраняются до повторной оценки старого контроля. Финальные преобразования, частоты классов, scaler таргета и модели обучаются только на доступных train; внешние метки не нужны.

**Повторная оценка.** Период 5 и классификационный control уже просматривались ранее. Новая оценка на них является повторной проверкой на использованных данных, а не свежим слепым свидетельством. Сравнение с прежними сохранёнными прогнозами возможно на тех же строках. Изменение финального CSV не будет представлено как доказанный рост качества на скрытом test.

Ресурсы: без запросов управляющей модели, без новых скачанных зависимостей, четыре CPU-потока на последовательный worker, 180 секунд на пробное обучение, до 300 секунд на refit, дедлайн первоначальной серии 3 600 секунд. После её результата отдельно добавлена факторная проверка двух вариантов XGBoost с собственным пределом 900 секунд; прежние предсказания переиспользованы. Это бюджеты локального reference-исследования, не лимиты EDA-режима. Конкурсные ограничения и настройки не меняются.

## Что намеренно не переносится из источников

- Оригинальные размеченные CSV из WiDS/UNSW не скачиваются и не объединяются с данными организаторов.
- Чужие веса, готовые прогнозы и восстановление меток по внешним ID не используются.
- Высокие Accuracy, бинарный F1 и Macro F1 из других разбиений не считаются сопоставимыми баллами.
- Предобученные табличные модели исключены требованиями конкурса, даже если выглядят сильными в бенчмарке.
- Дорогой полный поиск FT-Transformer/RealMLP не заявляется выполненным. Небольшой sklearn MLP проверяет конкретный доступный нейросетевой рецепт и не опровергает другие нейроархитектуры.
- Псевдоразметка не добавлена без проверки: обучение студента на собственных прогнозах может закреплять ошибки и требует воспроизведения трансдуктивного протокола на каждом валидационном разбиении.
- Статистическая уверенность и перенос на следующий год/другую сессию не выводятся автоматически из числа обучений или прохождения тестов.
