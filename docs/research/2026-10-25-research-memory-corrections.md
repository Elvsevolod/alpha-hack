# Исправления по техническим проверкам, до внешней оценки

Исходное A/B сравнение зарегистрировано в `outputs/research_memory_ab_live_20261025/protocol.json`: A=`6b0c0cd`, B=`f57c9db`. Исполняемые копии не меняются во время серии. Внешние метки не открывались.

1. Полный офлайн-прогон обнаружил регрессию активной гипотезы: версия 3 сокращала changed_component до 256 байт вместо прежних 1024. Минимальное воспроизведение — `tests/test_context_integration.py::test_current_hypothesis_and_distinct_rejected_ids_remain_inline`. Прежние пределы восстановлены; новые опциональные проекции уступают им место. После исправления прошли 29 проверок context integration и внешнего оценщика, отдельно 17 проверок регрессии и памяти. Весь полный набор не завершён: остановлен после обнаружения ошибки, чтобы разобрать причину и не создавать конкуренцию за ресурсы. Успешной полной приёмкой этот запуск не считается.

2. В живой трассе A обнаружена амплификация чтений: research_options и непринятые native-предложения доставляются частями по 768 байт; агент потратил множество шагов на их последовательное чтение до первого принятого исследовательского обучения. Это наблюдение о маршруте и расходах, не доказательство единственной причины поведения модели. Новые руководства могли усилить проблему. Версия 4 публикует такие источники как обычные versioned records и предлагает существующий read_run_records с max_chars=12000. Меняются маршруты локальных руководств, research_options, research_memory, decision_frame и unexecuted_native_intents. API, разрешения, защищённые размеры и byte-continuations не расширены. Версии 1–3 сохраняют прежние byte-маршруты; закреплённый текст промпта прежней сессии не заменяется.

Полное чтение candidate_interface через публичный инструмент теперь проверяется одним действием; native и JSON HTTP-имитации получают результат каталога и читают выбранное руководство. Это измерение числа чтений конкретного документа, а не оценка качества рассуждений или общей экономии.

При широких проверках встретились ещё два таймаута в функциональных fixtures: custom-analysis с 20 секундами и parent Ridge с 12 секундами. Неизменённые проверки отдельно прошли за 10,30 и 13,65 секунды суммарно. Это не доказывает причину таймаутов; воспроизводимый функциональный дефект не найден. Такие проверки проверяют disclosure/inheritance/finish, а не скорость холодного старта. В них увеличен тестовый резерв до 45 секунд на worker и 120 на пару; runtime и отдельные проверки строгого дедлайна не ослаблены. Прежние остановки полного набора сохранены как неуспешные, без объявления исключённых проверок прошедшими.

Широкий прогон на `a845715`: 962 passed, 3 skipped, остановка на отсутствующем AutoGluon. Оставшаяся часть отдельно: 495 passed, 11 failed, 5 skipped. Девять этих failures связаны с отсутствующим AutoGluon; два — с устаревшей предпосылкой stress-теста: после сокращения SYSTEM фиксированные 100 повторов больше не переполняли native framing. Давление теперь рассчитывается от фактического размера; проверка по-прежнему требует превышения 65536 для native и успешного JSON без увеличения лимита.

Три unit-теста, уже использовавшие собственный fake Predictor, получили изолированный fake module/trainer API и выполняются без настоящего AutoGluon. Это проверка логики нашего адаптера, не реального ML. Реальные integration-проверки помечены условием наличия зависимости; локально они явно skipped, в полном окружении запускаются. Docker daemon недоступен, новая проверка настоящих AutoGluon/LightAutoML не состоялась. Отдельная регрессия подтверждает отказ CapabilityRegistry до исполнения при отсутствующем пакете. Никаких пакетов в runtime не устанавливается.

3. Добавлен независимый офлайн-оценщик. Он сначала требует технический аудит, затем фиксирует запрет продолжения серии до первого чтения labels. Проверяются точная схема опубликованного CSV, количество и порядок ID, уникальность, классы и конечность чисел. Тесты на известных синтетических данных подтверждают Macro F1=1 и RMSE=0 и отказ при перестановке ID. Внешняя оценка реальных запусков выполняется только после фиксации всех сравниваемых исправлений.

Отдельные ошибки A — запрос неподходящего source version/scope и неподдерживаемый параметр is_unbalance — не считаются плохим качеством семейства. Исполнитель их отклонил. Автоматической подмены параметров, ослабления границ или подгонки под Adult нет.

Для этой подтверждённой нехватки интерфейсной информации версия 4 добавляет условное руководство runtime_parameters. Список принимаемых канонических ключей строится непосредственно из PARAMETERS исполнителя, за исключением controller-owned ключей, и закрепляется вместе с остальными руководствами. Это контракт адаптера, не обещание поддержать весь API библиотеки, не рекомендация значений и не обязательная стадия чтения. Тест проверяет совпадение с исполнителем и доступ через публичный инструмент. Ни один новый параметр автоматически не разрешается.

В smoke HPO A причина `Optuna completed no valid inner trial` подтверждена в worker.log: доля subsample ниже 1 без положительной subsample_freq. Прежний результат скрывал это условие. Для каждого sampled direct-рецепта теперь вызывается та же проверка совместимости на публичных recipe/TaskSpec; её причины сохраняются в истории failed trial и кратком сообщении при отсутствии успешных trial. Ошибки стороннего backend передаются только как тип исключения, без произвольного текста и данных. Запрещённые комбинации не разрешаются и не исправляются автоматически. Адресные тесты подтверждают отсутствие обучения для такого рецепта и отсутствие sentinel из приватных признаков/исключений в новой публичной обратной связи.

Исправленная версия требует отдельного живого сравнения. Результаты первоначального B нельзя приписать версии 4. Основная серия продолжает исполнять закреплённые исходники; улучшение предсказаний пока не заявляется.

Adult A завершил исследование из-за исчерпания исправлений ответа модели, затем штатно опубликовал сохранённого кандидата после control/refit. Это техническая защита итогового файла, не обоснованное решение агента закончить исследование. В новый промпт добавлено предложение использовать краткие аргументы, наследование и существующие recipe patches вместо повторной сериализации полного рецепта. Это проверяемая гипотеза о снижении избыточного вывода; она не устраняет гарантированно усечение reasoning и не считается доказанным улучшением.

Adult B завершился самостоятельным finish, но обоснование объявило robust local optimum и отсутствие native derived-feature transform. Конечные отрицательные варианты этого не доказывают; в реальном FrameTransform есть math через MathFeatures/RelativeFeatures и другие операции создания признаков. Уточнено общее правило для новых запусков: ограничивать вывод проверенным пространством, не выводить общую причину ошибок из неудачного вмешательства, подтверждать заявления о недоступности интерфейсом и обозначать непроверенные эффекты предположениями. Завершение с неизученными альтернативами допустимо. В справку включён список имён Transformation непосредственно из собственной схемы. В native/JSON после максимального сжатия правило доступно; шесть адресных проверок проходят. Польза для живого обоснования ещё не установлена.

В том же finish B называет опыты single-change, включая смену семейства и нескольких параметров одновременно. Полный review уже содержит фактический diff. В компактную карточку дополнительно выведены его basis, число изменённых полей и mixed-флаг; заявленный changed_component остаётся отдельно как agent_assumption. Это помогает увидеть противоречие без восстановления детали по собственной памяти. При тесном контексте сохраняется прежний маршрут полного чтения, лимит защищённого ядра не увеличивается.

Уточнение тестового harness: для следующих серий внешний watchdog останавливает процесс точно на границе выделенного времени, без прежних 30 секунд допуска; фиксируется SHA CSV на дедлайне. Исходная уже исполняющаяся серия использует прежний harness с 30 секундами допуска снаружи, при этом внутренний runtime ограничен исходными 10800 секундами. Этот предел проверки нельзя смешивать с доказательством точного внешнего hard kill платформы.

Исправлен также учёт снимка лимитов: код возврата 3 скилла означает успешно полученный exhausted/blocked, а не неизвестный баланс. Будущие серии закрепляют SHA самого harness и отклоняют его незаявленную смену до обращения к API. Этот контроль относится к воспроизводимости тестов, не к восстановлению конкурсного агента.

Позднее в той же трассе A виден повторный возврат к источнику unexecuted_native_intents после изменения его версии. Это известные неисполненные предложения, а не неизвестный исход операции. Для версии 4 значение явно помечено optional/recovery_required=false, а промпт различает такие предложения и операции, требующие восстановления. Предложения не исполняются автоматически, не удаляются и не становятся обязательной очередью. Это исправление смысловой подачи по наблюдаемой трассе; эффективность на живой модели ещё нужно измерить.

Уточнение пользователя: каждая конкурсная задача стартует с нуля. Исследовательская память относится к опытам текущей задачи, не переносится между задачами и не требует возобновления прежнего запуска. Нового обязательного этапа восстановления нет. Существующие проверки восстановления оставлены как регрессии инфраструктурных гарантий; их прохождение не является улучшением решения ML-задачи. Осторожность при неизвестном исходе сетевого вызова нужна и внутри одного запуска, чтобы не повторять неизвестно завершённую работу.

В Adult A (вызов 73) и Bank B (вызов 50) обнаружена общая причина преждевременной остановки: известный ответ `finish_reason=length` достиг потолка обычного режима 8192 токена и ошибочно трактовался как окончательная недоступность Qwen. При этом уже настроенный сложный режим допускает 12288 токенов с потолком 24576. Для новых запусков версии 5 такой исход передаётся существующей политике ошибки следующего шага, которая выбирает сложный режим. Частичный ответ полностью отбрасывается, даже если содержит синтаксически завершённую команду. Потолки режимов, дедлайн, резерв финализации и запрет повторять неизвестный исход не меняются. Сохранённые версии 1–4 и достижение максимального сложного потолка сохраняют прежнюю остановку. Это изменение обработки известного усечения, а не новый ML-исполнитель или дополнительная роль.

Регрессии HTTP native/JSON проходят весь Controller.run: усечённый finish не принимается, следующий запрос использует существующий сложный бюджет, затем выполняются control/refit и публикация CSV. Отдельно проверены прежняя версия и максимальный потолок. Вместе с settings, stream, context integration, layered context и branch memory: **96 passed за 325,88 с**, `/tmp/alpha-qwen-capacity-regressions.xml`. Живое улучшение завершения новой версии ещё не измерено.
