# CatBoost: JSON-веса и порядок классов в native метрике

Общая ML-цель остаётся активной. Следующий участок аудита обоснован требованиями одного агента для неизвестных задач, подтверждённых меток и честного внутреннего выбора, сопоставленными с ТЗ в `2026-10-26-agent-path-audit.md`. Новая модель или DL production-интеграция не добавляется.

## Что проверено и найдено

Начальная проверка sample weights обнаружила существующее выравнивание по `X.index` перед native fit, сортировку вместе с ranking rows и намеренный запрет наследования родительских domain weights в строгий OOF. Эта защита не ослаблялась. Это чтение конкретных путей, не полная сертификация всех weighted composition.

Продолжен явно оставленный ранее участок `class_weights` у CatBoost (отдельный параметр от `class_weight` других семейств). На синтетических данных с подтверждёнными числовыми классами `[0,1]` корректный JSON `{"0":1,"1":4}` успешно проходил fit, но CatBoost извлекал из ключей **строковые** class names. Следующий predict падал с `ValueError: '0' is not in list`, поскольку контракт требовал числа. Нестандартные числовые классы тоже не переносились корректно. Никакой исторический organizer failure этому дефекту не приписывается.

Отдельно найдено расхождение native stopping metric. CatBoost использует порядок ключей словаря для внутренней кодировки меток, а callback интерпретировал его как отсортированный порядок. Для ключей `{20:1,10:4}` и binary F1 с positive label `20` воспроизведены **0.877551** в кривой и **0.454545** по фактическим прогнозам. Это пример неправильной метрики остановки, а не прирост качества после исправления. Macro F1 может маскировать такую перестановку, поскольку симметричен к общей перенумерации классов.

До изменений новый минимальный набор дал **11 failed / 2 passed**. Строковые метки уже работали; они сохранены как положительный контроль.

## Исправление

- Ключи словаря восстанавливаются только в однозначно подтверждённые метки через общий Decimal-based resolver. Строковые числовые метки остаются строками. Позиционные индексы вместо неизвестных строковых меток не угадываются.
- Для CatBoost словарь должен покрывать все подтверждённые классы: этот backend выводит class names из ключей, поэтому частичная карта не трактуется как неявные единицы. Неизвестные ключи, неоднозначности, нечисловые/отрицательные/нефинитные веса и нулевой вес всей наблюдаемой популяции отвергаются публичной диагностикой без печати присланных значений.
- На конкретном inner fit в native constructor передаются только наблюдаемые классы; исходная полная карта остаётся в frozen recipe и восстанавливается при полном refit. Веса отсутствующего редкого класса не удаляются из рецепта.
- Активные `auto_class_weights` и явные `class_weights` не смешиваются. Типизированный словарь привязывается отдельно для каждого target перед созданием обучаемой модели.
- Callback использует фактический порядок ключей локального CatBoost-словаря. Публичные probability columns по-прежнему выравниваются к объявленным TaskSpec classes.

Документация получена через Context7 (resolve-library-id → query-docs): [параметры CatBoost](https://github.com/catboost/catboost/blob/master/catboost/docs/en/references/training-parameters/common.md). Она подтверждает извлечение class names из ключей и несовместимость двух режимов весов. Исполнение проверено на установленном **CatBoost 1.2.8**; ссылка на текущий master не объявляется snapshot этой версии.

## Проверки и ограничения

Итоговый новый набор — **17 passed**. Проверены числовые и непоследовательные метки, обратный объявленный порядок, обычные и числовые строки; JSON → fit/predict → native probability alignment → pickle → frozen JSON replay; отсутствующий inner-класс и full refit; неправильные карты до preprocessing; конфликт автоматических весов; независимая проверка binary stopping F1; реальный Optuna → frozen replay. Отдельный Controller → JSON → worker сценарий обучает сохранённую CatBoost-модель с числовыми ключами, а неверная карта отвергается. Control не открывается, реальных LLM calls — 0. Регрессионно проверены существующие native positional lists на числовых и строковых метках; этот фикс не меняет их интерпретацию.

Связанный набор с `class_weight`, boosting schedules и learning tests дал **71 passed** до добавления последних двух list-кейсов. Наборы пересекаются и не суммируются. В финальном worker-fixture CSV читается с `keep_default_na=False`, чтобы строковая категория `NA` случайно не превращалась в пропуск при подготовке теста. Промежуточные и финальные XML и их SHA, source SHA и команды находятся в `research/agent_path_audit_20261026/catboost_weights.json`.

Новых fit исправление не добавляет; оно меняет привязку короткого словаря и метрику остановки. Прирост Macro F1/RMSE на организаторских задачах не заявляется. Исправленный путь — direct и внутренние direct trials Optuna; прохождение dictionary weights через вложенные AutoML adapters этим этапом не сертифицируется. Крупный ресурсный прогон и автономность Qwen остаются отдельными незавершёнными проверками.

Реальных API-вызовов организаторов — **0**; alpha-api-limits для чисто офлайн-работы не требуется. Перед потенциальной живой серией отдельно прочитаны правила лимитов и проверены существующие процессы/контейнеры без вывода ключей/окружения; новая API-серия не начиналась. Main, конкурсный ZIP и чужие контейнеры/процессы не изменялись. Старый отрицательный вывод по пользе авторского RealMLP не пересматривается без новой сопоставимой проверки; общий goal не завершён.
