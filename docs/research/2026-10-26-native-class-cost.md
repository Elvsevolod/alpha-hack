## Найденные расхождения и изменения

Прежний прогноз зависел от строк/раундов, но summary не передавал наблюдавшееся число классов. Теперь SearchPipeline сохраняет versioned class_work: количество классов только в предоставленном fit и размер уже подтверждённого TaskSpec. При refit запись обновляется. Новых обращений к validation/control targets ради прогноза нет.

Прогноз использует **консервативную единицу native output work**: binary=1, multiclass=K. Fit-фактор взвешивается измеренным selected_fit_actual_seconds каждого target; при отсутствии времён применяется максимум. Для native model inference/serialization и repeatable auxiliary work применяется максимальный фактор. Если counts не растут, фактор равен 1; constant-ветка исключена. При отсутствии metadata сохраняется legacy-формула с явным basis=no_class_work_metadata. Новая metadata с некорректными counts отклоняется.

**Это не калиброванный коэффициент времени.** Например, измеренное ускорение стоимости 2→10 — около 2.2×, а коэффициент native work — 10. На малых задачах политика может заметно завышать резерв. Фиксированный intercept измеренной fit-curve, запуск интерпретатора, staging/load, отдельная worker initialization и fixed prediction overhead не умножаются на число классов. Output rows масштабируются отдельно от fit rows. Факторы и их некалиброванный basis видны в completion graph. Прогноз не считается гарантией дедлайна; внешний монитор и резервный CSV сохраняются.

Дополнительно найдено, что SearchPipeline.refit возвращал новую сводку, но в сериализуемом self.summary оставалась исследовательская фаза. На новых class counts это дало **12 failing native tests**: сохранённая и возвращённая сводки расходились. Теперь self.summary обновляется, в том числе rows и class_work; worker проверяет совпадение pickle с manifest. Это предотвращает повторную поправку для уже расширенного класса. У all-constant AutoML также исправлены training_keys/selected_fit_rows: actual fit использует все строки, а не inner-fit; native class multiplier к нему не применяется.

## Проверки и ограничения

Финальный связанный набор **71 passed**, включая фазовые расчёты, completion graph/recipe identity, бюджет финализации, real native 2→3/3→4 class refit, rare-class preservation и iteration aliases. Отдельно **3 guarded worker/CSV tests passed**, metadata прошла сериализацию. Группы пересекаются с прежними проверками. Отрицательный stale_summary_before.xml сохранён; это воспроизведение дефекта, не промежуточная ошибка fixture.

Серия измеряет native fit/predict/pickle и свежий Python-процесс; не полный controller/Qwen lifecycle. Память и дисковый резерв финального dependency graph не получили новой class-aware модели: их корректность при крупном расширении класса остаётся открытой проверкой. Для старых артефактов без metadata восстановление неизвестных class counts не изобретается. Нужны калибровка на масштабе, оценка влияния завышенного резерва на допуск полезных кандидатов и итоговое качество агента.

Среда — Python 3.12 native development, pinned AutoGluon 1.3.1 / LightGBM 4.6.0 / CatBoost 1.2.8 / XGBoost 2.1.4. Не полный Linux-стенд конкурса. Чужие процессы/серии не останавливались; серия шла последовательно с одним CPU. Sandbox сначала запретил ps, затем разрешённый read-only просмотр выполнен отдельно. Нулевую конкуренцию за ресурсы по этому наблюдению не заявляем.

API calls **0**; alpha-api-limits для офлайн-серии не требуется. Organizer control не открывался, RMSE/Macro F1 не измерялись, самостоятельный выбор Qwen не проверялся, ZIP и PyTorch production не расширялись. Общая цель активна.
