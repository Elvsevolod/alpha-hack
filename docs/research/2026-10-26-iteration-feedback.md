# Выбранные итерации в компактной обратной связи

В [диагностике переноса stopping](2026-10-26-temporal-iterations-result.md) воспроизведены68/216 итераций двух реальных моделей. Их короткий feedback показывал параметры1500/4000 и метрику, но schedule был доступен только в полном measured record. Pipeline view содержит fresh recipe, поэтому не заменяет чтение результата остановки. Полная информация не терялась, однако в обычном переданном контексте это различие не было видно непосредственно.

Добавлен training_iterations в compact experiment summary для completed boosting results с реально сообщённым schedule. Источники: learning_curve.iterations (selected с допустимым selection_scope) и budget.iteration_schedule (applied_schedule). Recipe parameter показывается отдельно именем/значением для direct. Для Optuna начальный параметр не объявляется пределом выбранного trial. Если чисел нет, они не заполняются из cap; failed/timeout/unknown не выдаются за завершённое обучение. Параметр applied_schedule означает применённую конфигурацию обучения, не независимый физический счётчик деревьев: native learners могут завершить рост раньше из-за отсутствия допустимых разбиений.

Только подтверждённые targets, записанные по индексам полного TaskSpec, входят в сводку; чужие keys/нецелевые поля не копируются. Длинные имена не сокращаются до похожих идентификаторов. Блок ограничен512 bytes. Для широкого multioutput указывается число пропущенных targets и точный read route к полному record. Когда все числа помещаются, дополнительный маршрут не дублируется: enclosing history card уже содержит полный source read. Общий summary остаётся≤1536 bytes.

Приоритеты существующей temporal stability и class feedback сохранены. Малые declared hyperparameters помещаются перед длинным перечнем changed-field names и дополнительными weakest slices. На исторических данных первоначальная компоновка вытесняла параметры лидера; аудит это обнаружил, приоритет скорректирован и закреплён тестом. Общее field_count остаётся полным, даже если список имён изменений сокращён. На read-only проекции реальных baseline/leader теперь одновременно видны1500→selected68/applied68 и4000→selected216/applied216, сохранены все исходные hyperparameters, итоговые размеры1536/1518 bytes. Исторический журнал не переписывался.

На stage0 training_iterations виден в history_details. На stages1–3 сам compact summary по прежним правилам сжатия удаляется, но baseline/leader ID и существующие публичные чтения позволяют получить полный measured record. Новое поле не объявляется защищённым inline на всех стадиях и не увеличивает protected core. Уже опубликованные immutable summary sections не пересобираются задним числом; новые summaries появляются при индексации новых результатов.

Проверки:24 passed за9,60s, outputs/iteration_feedback_20261026/final_verified.xml. Проверены разные selected/applied значения, отсутствие ложного cap fallback, noncompleted results, Optuna, широкие многоязычные targets, byte bounds, сохранение небольших hyperparameters при насыщенном feedback, существующие stress/class summary priorities. Реальный Controller fixture обучает baseline; в native/JSON на всех четырёх stages проверены stage0 поле и lossless чтение budget schedule. CSV/control не менялись. Последовательные промежуточные прогоны тех же проверок не складываются как независимые подтверждения.

[Ledger](../../research/iteration_feedback_20261026/summary.json) содержит read-only историческую проекцию без данных/моделей и отмечает ограничения. Qwen API не использовался, новых контрольных метрик нет. Оптимизатор, early stopping, default tree counts и production ZIP не менялись. Это улучшение точности ML-feedback, не измеренный выигрыш самостоятельного агента. Следующая необходимая проверка — использует ли Qwen эти сведения для более полезных экспериментов при том же полном бюджете.
