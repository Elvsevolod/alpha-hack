# Объявленный класс впервые появился при selection refit

В `c3dd300` такой refit честно отклонялся, поскольку сохранённый LabelCleaner не кодировал новую наблюдавшуюся метку. Теперь для native GBM/CAT/XGB в selection-профиле реализован полный fit на предоставленных строках без нового исследования. Класс должен уже входить в подтверждённый TaskSpec; добавление неизвестной метки по-прежнему запрещено.

## Исполнение замороженного рецепта

Новый AutoGluonClassRefit сохраняет выбранный класс нативной модели и её user hyperparameters, добавляет измеренные params_trained и пересоздаёт только кодирование объявленных меток. Копия общего feature_generator применяется через transform, без нового fit. Нативная модель обучается один раз без validation, HPO, нового inner split и stopping-решения. После fit фактическое число раундов сверяется с выбранным; незавершённое расписание не публикуется как полное.

При изменении количества наблюдавшихся классов AutoGluon заново выводит зависимые от задачи defaults: например, бинарная цель становится multiclass для того же объявленного пространства TaskSpec. Явно заданные параметры не заменяются; несовместимая явная цель остаётся ошибкой. Поддержка всех сочетаний параметров не заявлена. Общий feature generator заморожен; внутреннее preprocessing конкретной native-модели проходит её обычный fresh fit, как у штатного refit template.

Исходный predictor и его файлы не изменяются. Следующий refit использует тот же frozen native recipe; сериализация сохраняет его и новый LabelCleaner. Копирование параметров не увеличивает повторно max_memory_usage_ratio. Inference передаёт CPU-лимит явно; row identity и порядок проверяются после feature transform. Registry version 7 и описание публичной схемы отражают новую возможность.

В AutoGluon XGBoostModel 1.3.1 params_trained остаётся пустым после fit без validation. Для этого пути проверяется фактический num_boosted_rounds и сохраняется измеренный n_estimators. Это позволяет повторять frozen refit, не возвращаясь к исходному cap.

## Доказательства

До изменения три настоящих GBM/CAT/XGB сценария завершались прежним отказом. Итоговые проверки охватывают:

- **12 native сценариев**: три семейства × переходы 2→3 / 3→4 класса × строковые / числовые метки. После первоначального поиска — ровно один дополнительный native fit на 180 строках, без validation; новые метки имеют вероятности, порядок колонок соответствует TaskSpec. После pickle выполняется ещё один такой fit. В каждом сценарии TabularPredictor.fit и inner_split вызываются только один раз, при первоначальном поиске. Предсказания исходного predictor сохраняются.
- **3 отдельных guarded worker**, по одному на семейство: штатный Executor/worker_entry с Python -I, ограничением 1 CPU / 2048 MiB / 45 s, сериализацией, typed predictions и настоящим Publisher. Проверены CSV, ведущие нули ID, порядок и метки. Новый артефакт работает после переименования исходного source-каталога, то есть не требует прежних файлов predictor для inference.
- **46 passed** в связанном наборе основной среды: новые native cases, rare-class retention, iteration aliases, weights boundary/recovery в native/JSON, selection/full refit, exact-group bagging/stacking и reference memory. Отдельный worker-набор — **3 passed**. Это разные технические проверки, не независимые подтверждения качества.

На малых 180-row worker сценариях наблюдались около 1.15–1.30 s wall и 182–198 MiB peak worker RSS; точные результаты и повторные наблюдения закреплены в summary. Время включает запуск процесса, fit, inference и сериализацию, но не первоначальный поиск и не последующую публикацию CSV в родительском процессе. RSS измеряется выборками Executor; общий расход родителя отдельно здесь не отчётный peak. Это не стоимость конкурсного агента. При большем числе классов число деревьев/векторных компонент на один раунд может вырасти; прогноз такого изменения на больших задачах ещё требует проверки.

Среда — native Python 3.12 с разрешёнными пакетами AutoGluon 1.3.1 из ignored development overlay. Для Python -I создана отдельная локальная venv с .pth-путями к уже имеющимся библиотекам; основная venv и requirements не менялись. В worker-тесте явно разрешено чтение этих trusted library roots, как обычное чтение зависимостей под sys.prefix; production Executor/access policy не менялись. Смешанный запуск 49 тестов в overlay дал 47 passed / 2 failed: прежние HTTP-фикстуры не передавали off-prefix roots своим direct worker и получили PermissionError. Подтверждённый положительный основной набор выполнен в исходной venv, а worker-набор — в зарегистрированной overlay-среде. Отрицательный XML сохранён, ограничения чтения не ослаблялись.

Новое поведение сертифицировано для проверенных selection-рецептов; migration старых trained iteration-alias артефактов, полный Linux 8 CPU / 32 GB / 3 h run и организационный score не подтверждены. Качество модели, корректность интеграции и автономность Qwen не смешиваются: новых organizer RMSE/Macro F1 нет, реальный выбор Qwen не проверялся. API calls 0; alpha-api-limits для этого офлайн-этапа не требуется. ZIP/PyTorch production не расширялись. Общая цель активна.
