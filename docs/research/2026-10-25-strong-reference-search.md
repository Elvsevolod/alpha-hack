# Поиск улучшения сильного решения

Рабочая ветка: `feat/strong-reference-search`. Основа — main v101; исторический лучший dev-рецепт и его исполнение сохранены в `df36940`. Источники baseline читаются из локального Git в каталог результатов; конкурсный контейнер и интернет для обучения не используются.

## Что означает универсальность

Агент может выбирать предметные признаки из описания задачи и словаря, в том числе отношения величин, категории и внутренние иерархии. Универсальны инструменты, границы данных и процесс проверки. Не требуется один фиксированный набор признаков для всех задач. Предметный reference-driver не выдаётся за самостоятельно выбранное действие Qwen.

## Точка сравнения

Сохранённый регрессионный ансамбль: 50% CatBoost с инженерными признаками и 50% регуляризованного LightGBM, RMSE **39,0361472203** на ранее просмотренном временном контроле. Классификация: 50% weighted XGBoost + 50% иерархического LightGBM, prior correction и fit-only offsets, Macro F1 **0,6565257846** на ранее просмотренном групповом контроле.

Это локальные метрики. Они не переводятся напрямую в конкурсные баллы. Сильные ансамбли должны сравниваться на тех же строках и с тем же правилом решения; слабое дерево из PyTorch-пилота больше не используется как основной ориентир.

## Проверяемые вопросы

| Наблюдение | Гипотеза | Проверка | Решение |
|---|---|---|---|
| Категории описывают разные масштабы величин | Отклонения от типичных значений внутри категории могут дополнить дерево | Fit-only median, global IQR, относительное отклонение и frequency; до восьми важных числовых координат | Проверяется отдельно и в малой смеси |
| Сильный ансамбль зависит от случайного seed | Повтор с seed 7 уменьшит дисперсию | Те же семьи и рецепты, сохраняются отрицательные результаты | Seed не выбирается по control |
| Поздние деревья могут чрезмерно специализироваться | DART даст другие ошибки | Fixed 600 rounds, без неподдерживаемого early stopping | Не путать другую модель с гарантированным улучшением |
| Короткий CatBoost ранее был ограниченным конкурентом | Более содержательный native-рецепт способен дополнить XGBoost/иерархию | 700 rounds, depth 7, SqrtBalanced, исходные категории | Оценивать по Macro F1 и переносу |

### Почему такие методы

[DART](https://proceedings.mlr.press/v38/korlakaivinayak15.html) использует dropout деревьев как способ борьбы с чрезмерной специализацией ансамбля. Это основание для гипотезы, а не обещание нашего улучшения. В [LightGBM](https://lightgbm.readthedocs.io/en/stable/pythonapi/lightgbm.early_stopping.html) DART не поддерживает обычный early stopping: число итераций фиксируется заранее.

Дополнительные кандидаты для следующего ограниченного сравнения: более глубокие деревья, упорядоченный boosting CatBoost, линейные модели в листьях и ограниченные специалисты по путающимся парам классов. [LightGBM linear_tree](https://lightgbm.readthedocs.io/en/stable/Parameters.html#linear_tree) требует контроля масштаба, памяти и обработки пропусков. [Pairwise coupling](https://papers.neurips.cc/paper_files/paper/1997/hash/70feb62b69f16e0238f741fab228fec2-Abstract.html) мотивирует бинарные границы; ограниченная корректировка пары не является воспроизведением полного алгоритма coupling.

## Протокол

Регрессия: два forward development-среза из сохранённого reference; выбор по среднему RMSE, затем единственная проверка выбранного compound на прежнем control. Классификация: тот же fit и два взаимно дополнительных group calibration/selection среза. Offsets обучаются на calibration, метрика сравнения считается на противоположной selection. Два среза классификации используют один fit и перекрываются как области — это не две независимые репликации.

Веса добавленного кандидата заранее ограничены 0, 0,2, 0,4 и 1. Ноль сохраняет baseline. Набор весов — инженерный бюджет поиска, не универсальные правила агента. При refit групповые статистики учатся заново на разрешённой увеличенной области. Это часть алгоритма, а не использование контрольных меток.

Основные библиотеки сверены с requirements организаторов: numpy 1.26.4, pandas 2.2.3, scipy 1.12.0, scikit-learn 1.5.2, CatBoost 1.2.8, LightGBM 4.6.0, XGBoost 2.1.4, joblib 1.4.2, psutil 6.1.1. Установка пакетов, внешние веса и API-вызовы отсутствуют. Native estimators используют 2 потока, историческая hierarchy — до 4; оба укладываются в 8 CPU из ТЗ. Ограничение dev-worker: 180 секунд и 4 ГБ RSS, общий deadline серии 1200 секунд; RSS проверяется для самого worker, модели используют потоки.

## Найденные технические проблемы

- Первое выполнение остановилось до обучения: parent и worker одновременно создавали один каталог. Исправлено идемпотентное открытие worker-каталога; исходный неуспешный запуск сохранён.
- В macOS sandbox нельзя перечислять все процессы через psutil. Для этих native learners достаточно измерять RSS своего worker: они используют потоки, а не дочерние процессы.
- Typed whitelist текущего runtime не включает параметры DART. Dev-кандидат явно задаёт три проверенных параметра на экземпляре того же LightGBM; production whitelist не расширяется молча.
- Importance после one-hot нельзя сопоставлять исходным столбцам через zip. Используется `get_feature_names_out`, отдельная регрессия проверяет expanded mapping.
- Исторический `audit/prediction.npy` содержит final-test прогноз в старом driver. Для аудита baseline заново предсказывает нужные control-строки сохранёнными моделями. Перед выводом требуется точное воспроизведение обеих контрольных метрик.

## Уже полученный отрицательный результат

Контекстный LightGBM в смеси 20% улучшил средний development RMSE с 47,168747 до 47,059262, но ухудшил control с **39,036147 до 39,428588**. Гипотеза отклонена для продвижения. Выбор не пересматривается после просмотра этого контроля. Рабочий CSV не изменяется.

## Граница доказательства

Это offline-разработка методов на предоставленных примерах с ранее использованным контролем. Здесь не проверяются самостоятельный выбор Qwen, полная трёхчасовая траектория, конкурсный Linux-контейнер или официальный балл. Нельзя выдать успешный unit-тест, улучшение development или новый CSV за доказательство этих свойств.

### Исправление сравнительного протокола

При проверке происхождения прогнозов обнаружено: старые regression `regularized_lgb_cv*` выбирали число итераций по самому оцениваемому периоду. Например, один cache содержал 71 дерево вместо фиксированных 1035 у принятого рецепта. Его development-прогнозы — **search validation**, а не честный forecast зафиксированного incumbent.

Это делало сравнение фиксированных новых кандидатов с ним несопоставимым. Старые циклы сохранены как исторические; их контрольные сравнения остаются воспроизводимыми, но development-контраст требует этой оговорки. Отдельный `reconcile_reference_selection.py` проверил совпадение строк и заново выбрал кандидата по уже существующим fixed-round forecast. Выбор до повторно используемого аудита запечатан отдельно; глубокий CatBoost снова не прошёл контроль. Результат не скрывается и не заменяет отрицательные старые циклы.

### Что помогло

В [forward_calibration_study.py](../../tools/forward_calibration_study.py) заново построены шесть fixed-round fit — два сильных участника на трёх прошлых origins. Остановка по будущему периоду отключена. Для каждого оцениваемого периода калибровка видит только прогнозы и метки **более ранних** периодов. Существующий `fit_blend` отклоняет менее двух реальных OOF-folds; отсутствие поддержки означает identity, а не фиктивные метаданные.

Проверены identity, существующие `weighted_oof` и `stacked_oof`, а также половинная и полная shrinkage-поправки групповых остатков. Их средний forward RMSE:

| Метод | Development RMSE |
|---|---:|
| Identity, фиксированный сильный ансамбль | 48,661708 |
| **Половинная групповая поправка** | **48,572630** |
| Полная групповая поправка | 48,707559 |
| Weighted OOF | 48,921416 |
| Stacked OOF | 49,403752 |

Поправка — global mean внеобучающих остатков плюс среднее отклонение для явно выбранных категориальных ролей. Категориальное отклонение сжимается множителем `n/(n+100)`, вся поправка — множителем 0,5. Числа 100 и 0,5 — параметры проверенного кандидата, не общие требования к агенту. Пропавшая/новая категория использует глобальную часть. Имена категорий и датасета не зашиты в вычислительное ядро [ResidualCalibration](../../automl_agent/residual_calibration.py).

Контрольная разница: **−0,199006 RMSE, примерно −0,51%**. Проверка чувствительности: 38 категорий улучшились, 22 ухудшились; исключение любой одной категории из расчёта оставляет прирост 0,163–0,304 RMSE. Это описательная проверка, не доверительный интервал и не подтверждение независимости объектов. Один старый контроль и один seed не доказывают перенос.

Native typed-режим residual calibration и самостоятельный выбор Qwen этим запуском не подтверждены; количество действий API, протокол валидации и конкурсный entrypoint не менялись.

## Проверки и воспроизведение

**75 адресных тестов прошли.** Проверены fit-only групповые статистики, unknown/missing категории, сериализация, mass-preserving парная корректировка, фиксированные параметры DART, lineage frozen forecasts, отсутствие автоматического повтора неуспешного worker, shrinkage на известном примере, выравнивание массивов, dependency policy, nested learning, инструкции и оба транспорта. Это не полный тест всего репозитория и не конкурсная приёмка.

Отдельный новый Python-процесс восстанавливает audit/final калибраторы и воспроизводит их прогнозы с `rtol=1e-12`. Сохраняются тесты и evidence предыдущего PyTorch-исследования; увеличение глубины не подменяет сравнение с сильным решением.

В development-среде с историческими reference-артефактами:

```sh
.venv/bin/python tools/strong_reference_study.py --output outputs/new_strong_cycle --seconds 1200
.venv/bin/python tools/strong_reference_study.py --extended --output outputs/new_extended_cycle --seconds 1200
.venv/bin/python tools/forward_calibration_study.py --output outputs/new_forward_meta --seconds 600
.venv/bin/python tools/forward_calibration_study.py --output outputs/new_forward_meta --export-to outputs/new_candidate
```

Каталоги должны быть новыми. CLI фиксирует версии, сверяет источники и сохраняет параметры; контрольные строки используют отдельную audit-фазу. Исторические joblib и большие `outputs/` не включены в Git: для чистого клона сначала нужны воспроизведённые reference-артефакты из `df36940`. Эта зависимость относится к сравнительному dev-harness. CSV-кандидат, отчёт и [полные числовые evidence](2026-10-25-strong-reference-evidence.json) доступны в ветке без этих бинарных моделей.

Расход API — **0**; реальные Qwen-вызовы, конкурсный ZIP и отправка организаторам не выполнялись. Ограничения: адаптивное исследование на уже использованных данных, единственный контрольный период и seed, отсутствие официального балла и полного автономного прогона в Linux. Улучшение локального reference не снимает этих ограничений.
