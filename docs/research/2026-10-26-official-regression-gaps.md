# Открытые проверки после падения v101 → v116/v120

По предоставленному пользователем скриншоту: v101935,654/8290,5s; v116280,084/7327,6s; v120330,758/6781,6s. Это итоговые баллы платформы, а не непосредственно RMSE/Macro F1. Формула, вклад отдельных задач, платформенные CSV и журналы не предоставлены. Причина падения не установлена; длительность и статус «Успешно» сами по себе её не определяют.

Последующее уточнение организаторов, переданное пользователем: оба сравниваемых запуска корректно отработали, обращения к LLM фиксировались, предсказания сохранены и зачтены; качество ухудшилось по обеим задачам. Для этих запусков ошибка доставки/незачтённый CSV исключены из объяснения падения. Пункт3 ниже остаётся исторической проверкой происхождения артефактов, а не актуальной гипотезой технического сбоя. Дальнейшая работа направлена на качество, выбор рецептов, остановку и перенос.

Точные архивы найдены: v101 из LFS, v116 из Downloads, v120 из origin/main c79e590. Проверены ZIP CRC, уникальность/плоский состав, синтаксис root Python, встроенный runtime SHA256 и каждый его файл. Внешний launcher и requirements одинаковы во всех трёх; requirements v116 совпадает с исходным организаторов. Это техническая проверка, не полная приёмка или доказательство качества.

## Что действительно не закрыто

1. **Связь исходников с поставкой.** Коммит c79e590 добавляет только38 ZIP/manifest файлов. Исходники automl_agent/context_compressor в main не обновлены относительно1c463e9, хотя внутри v116/v120 код изменён. Запуск тестов main или исследовательской ветки не проверяет эти поставки. Нужны восстановленный точный source commit/сборка и проверки извлечённого архива; механический merge архива не переносит runtime fixes в исходники.
2. **Слишком большой пакет без причинного сравнения.** v101→v116:43 изменённых/добавленных runtime файла,2510 добавлений/280 удалений; v116→v120:27 файлов,595 добавлений/204 удаления. Включены prompt, контекст, доступные методы, preprocessing, selection/refit и другие интерфейсы. Одного общего балла недостаточно для назначения виновника. Нужны одинаковые task/data/resource/model-channel условия для точных архивов и последующее отключение одной группы изменений. Не считать несколько seed на одном контроле независимым переносом.
3. **Происхождение фактически оценённого CSV.** В v120 новый source_paths.publish_template копирует sample_submission до тяжёлой инициализации; supervisor сохраняет аварийный CSV, но возвращает ошибку при ресурсном останове. Это путь сохранения шаблона, а не обученный прогноз. Не установлено, сработал ли он на платформе. Для каждого задания нужны last publication scope/hash, first_trained_csv, state, выбранный кандидат, full_refit rows и сопоставление реального CSV с refit predictions. Наличие файла или платформенный статус не заменяет эти сведения. Нельзя объявлять шаблон причиной330,758 без артефактов.
4. **Пилот способен ошибочно отбрасывать пригодный рецепт.** В последнем исследовательском live run кандидат exp_c95f0aaabf39d717 не дошёл до полного сравнения: performance_1/400 строк прошёл внешний OOF support check, затем потерял редкий класс во внутреннем stopping split. Точный offline replay показал корректные3 вложенных split на всех56974 разрешённых fit строках. Проверка исправлена в исследовательской ветке; новый quality gain и стоимость расширения не измерены. Этот код дефекта есть уже в v101, а также v116/v120, поэтому сам по себе он не объясняет деградацию между ними. Защита времени/групп/классов не ослаблена.
5. **Автономный поиск уступает сильной опоре.** [Matched классификация](2026-10-26-classification-matched-result.md): Macro F1 агента0,621310 против0,643884, wall801,61s против261,40s при одинаковом900s/CPU1/RAM3072MiB и точных строках. Только2 кандидата, из них один технический отказ;7 model calls,371,90s model channel, ошибки аргументов и существенный reserve. Это подтверждённый пробел выбора/эффективности агента, не подтверждённая потеря принятых ML-параметров. Предыдущее сопоставимое regression исследование также уступает сильной опоре:45,401 против42,185 RMSE.
6. **Неиспользованный потенциал ML.** Development-диагностика групп признаков улучшила regression45,5–43,5 до39,94, но это ручной выбор и не доказательство переноса. Диагностика остановки показала, что внутренне выбранные короткие schedules могут хуже переноситься на следующий период, хотя длинный cap хуже на внутренних origins. Автоматически включать cap или готовые признаки нельзя: агент должен обоснованно сравнить гипотезы внутри train. Новая v120 также меняет nonforecast temporal horizon с1 на15% внешних/20% внутренних периодов; на пяти Year_Factor периодах внешний horizon остаётся1, эффект на иных задачах требует отдельной проверки.
7. **Качество отделено от работоспособности.** v101 acceptance явно real_qwen_quality_run=false и quality_advantage_established=false. Успешные unit/offline checks проверяют контракты. Не закрыта длительная Linux/разрешённые зависимости/7CPU/RAM/реальный Qwen репетиция именно итогового ZIP и перенос на неиспользованные задачи. Повторная проверка знакомого control — не blind подтверждение.
8. **DL не показал требуемого выигрыша.** [Авторская RealMLP CPU проверка](2026-10-26-pytorch-conclusion.md) отрицательна против сильных деревьев на задачах организаторов, смеси также не улучшили главные метрики и стоят дороже. Сохранять только экспериментальную опцию, не расширять production-интеграцию или объявлять Torch способом вернуть935 баллов.

## Проверка текущего исправления и передача

Добавлены реальные структурные тесты: tiny exact-group pilot с редким классом, который проходит внешний OOF check и теряет класс внутри stopping split, расширяется до поддерживаемого полного fit; действительно неподдерживаемый full fit остаётся отказом. Фактический сохранённый pilot request повторён offline без обучения/скрытого контроля/API.

51 затронутый/соседний тест прошёл. Расширенный набор дал4 ранее существовавших отказа:3 из-за отсутствующего локального autogluon и1 устаревшего ожидания обязательного продолжения поиска в A19. Те же4 отказа воспроизведены с validation.py из HEAD до исправления; они не скрыты и полный suite не объявляется зелёным. A19 не переписывался: действующая policy допускает finish с честной неопределённостью без квоты методов. Для полной приёмки потребуются разрешённое полное окружение и отдельное согласование ожидаемой policy/теста.

Новых обращений к API при этом аудите нет; уже завершённый matched run имел before/after564,426771→558,559797 из600 (+5,866973 counter за интервал, возможны другие пользователи ключа). Другие серии не запускались и не останавливались. Архивы не перезаписываются, новый submit не выполняется. Ветка готовится к push с конкретными исправлением, результатами и оставшимися проверками; возврат официального качества пока не доказан.
