# Насколько близки наши сети к авторским рецептам

Продолжение исследования после шести задач и трёх seeds. Три seeds меняют обучение, но используют те же оценочные строки: это не три независимых подтверждения переноса. Старые control-проверки не используются для настройки нового рецепта; их просмотр уже произошёл и не скрывается.

## Сопоставление реализации

| Компонент | Предыдущий прототип | RealMLP-TD-S | TabM из работы |
|---|---|---|---|
| Числа | Standard/quantile/piecewise/periodic | Robust median/IQR, range fallback, smooth clipping | Модифицированный quantile; отдельные варианты с PLE |
| Категории | Обучаемые embeddings, cap 2000 | One-hot всех категорий, бинарный столбец ±1 | One-hot |
| Сеть | 2×128, LayerNorm/ReLU/dropout 0,1 | 3×256, SELU для классификации / Mish для регрессии | MLP с адаптерами BatchEnsemble |
| Инициализация | В основном PyTorch defaults | NTP, normal hidden weights/biases, zero output | Специальная инициализация адаптеров; отдельный выход участников |
| Ансамбль | 4 головы, общий выход с rank-one множителями | Одна сеть | Обычно 32 участника |
| Оптимизация | AdamW, lr 0,002, clip norm 5 | Adam без decay, β₂=0,95, отдельные lr для scale/bias, coslog4 | Другой рецепт с настройкой гиперпараметров |
| Loss / остановка | Sqrt class weights, F1/RMSE, patience 7, 60 epochs | Label smoothing 0,1; 256 epochs; последний лучший inner class error/MSE | Совместная оценка ансамбля, усреднение вероятностей |

Это существенные различия. Предыдущие отрицательные результаты относятся к собственным ограниченным вариантам, а не к точному RealMLP или TabM. Источники: [RealMLP, таблица A.1 и приложение A.2](https://arxiv.org/html/2407.04491v3#A1.T1), [TabM, архитектура и практические модификации](https://arxiv.org/html/2410.24210v3#S3).

## Выбранный рецепт

Для CPU выбран опубликованный **RealMLP-TD-S**, упрощённый вариант авторов. Он сохраняет оптимизацию и параметризацию, но не требует PBLD, parametric activations и больших ансамблей. Это не полный RealMLP-TD. Полный `pytabkit` использует Lightning вне списка организаторов, поэтому пакет не устанавливается: выполнен небольшой порт на разрешённых PyTorch/NumPy/pandas.

Сверка проведена с `pytabkit@c126ea51187c5080b91f28d352481dbd3b2194b0`: [defaults](https://github.com/dholzmueller/pytabkit/blob/c126ea51187c5080b91f28d352481dbd3b2194b0/pytabkit/models/sklearn/default_params.py), [параметризация и smoothing](https://github.com/dholzmueller/pytabkit/blob/c126ea51187c5080b91f28d352481dbd3b2194b0/pytabkit/models/nn_models/nn.py), [coslog](https://github.com/dholzmueller/pytabkit/blob/c126ea51187c5080b91f28d352481dbd3b2194b0/pytabkit/models/training/scheduling.py), [drop_last](https://github.com/dholzmueller/pytabkit/blob/c126ea51187c5080b91f28d352481dbd3b2194b0/pytabkit/models/training/nn_creator.py). Лицензия и проверенные исходники сохранены в `research/pytorch_author_recipe_20261026/pytabkit_sources/`, они не импортируются конкурсным runtime.

Порт сохраняет: 3×256; NTP `W/√fan_in`; normal hidden weights/biases и zero head; front-scale с lr×6; bias lr×0,1; lr 0,04/0,07; β=(0,9;0,95), eps=1e-8; нулевые dropout/decay; 256 полных эпох, batch 256 с drop_last; smoothing 0,1; стандартный regression target; последний лучший inner epoch. При refit расписание остаётся рассчитанным на 256 эпох, не сжимается к выбранному checkpoint.

Явные адаптации: fit-median для числовых NaN до авторского preprocessing (официальный sklearn interface их отвергает); защита постоянного таргета; собственная последовательность случайных чисел вместо векторизованного Lightning. Для faithful-пути отсутствующие/неизвестные категории получают авторский нулевой вектор; их сырые статусы различаются в обработке. Следовательно, это близкий алгоритмический порт, а не заявление о побитовом воспроизведении авторского benchmark.

## Сравнение ресурсов и данных

Каждому из трёх независимых fresh-process arms — сильные деревья, RealMLP-TD-S отдельно, смесь — предоставляется одинаковый верхний бюджет 900 секунд, один вычислительный поток, watchdog 4096 MiB. В бюджет входят загрузка, preprocessing, все epoch-selection/OOF/refit, подбор решений, сохранение/восстановление и inference. Неиспользованное время не скрывается. Ни одному arm не добавляется HPO: сравниваются конкретные фиксированные рецепты, а не оптимумы по всему пространству при данном бюджете.

Смесь выбирает вес и классификационное решение только на fit-only OOF. Сеть для OOF выбирает эпоху ещё внутри собственного fit. Аргмакс и offsets сравниваются на отдельной групповой части OOF; выбранные offsets переобучаются на OOF-области. Внешняя development/control область не участвует ни в одном из этих действий. Числа, категории и масштаб таргета обучаются заново на каждом разрешённом fit.

Для регрессии сохраняется сильный CatBoost/LightGBM с half-residual calibration из всех предыдущих forward-origin прогнозов. Для классификации — сохранённые weighted XGBoost/иерархический LightGBM и prior correction. Сравнение дополнительно отделяется от исторического лучшего контрольного результата: более слабая новая калибровка не должна создавать видимость победы над известной опорой.

`freeze.json` фиксируется до серии: код, данные, рецепт, бюджеты, seeds, веса, decision procedure и статус просмотра контролей. Контроль организаторов уже просматривался в проекте. Adult/Bank/Bike control уже оценивались в предыдущей замороженной серии; HAR не открывался этим чатом, но мог использоваться в другой работе. Ни один из них не объявляется новым независимым тестом. Внешние test-метки дополнительных датасетов не читаются.

Авторский порт остаётся исследовательским инструментом. Production capability им не расширяется; качество модели, механика исполнения и самостоятельный выбор Qwen оцениваются отдельно.
