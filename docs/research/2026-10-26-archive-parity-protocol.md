# До запуска: проверка численной эквивалентности архивов

Ответ организаторов со слов пользователя: оба сравниваемых платформенных запуска корректны, LLM calls и predictions учтены; качество ухудшилось по обеим задачам. Ошибка доставки/незачтённый CSV исключаются из объяснения этих запусков. Проверка не предполагает повторное доказательство доставки.

Цель: отделить численную регрессию одинакового ML-рецепта от изменения выбора агента. Точные embedded runtime v101/v116/v120, уже проверенные по ZIP/member SHA256, исполняются в отдельных subprocess. Источники этих архивов не редактируются. Одинаковые локальные разрешённые библиотеки, CPU1/RAM3072MiB, seed42, лимит180s на каждый рецепт; это не контейнер организаторов и не сравнение полного качества агента.

Заранее фиксируются три общих рецепта: regression LightGBM native с cap1500/lr0.03/leaves63/minchild20/lambda1/colsample0.7/subsample0.8/freq1, log1p/naive, без остановки; regression LightGBM native cap1500/lr0.03/leaves31, early stopping100, original target; classification LightGBM native cap300/lr0.05/leaves31/class_weight balanced, class_offsets/pooled_oof. Других вариантов по результатам не выбираем. Используются точные fit и validation из прежних bounded agent runs. Для классификации actual worker strategy exact_group, для регрессии temporal. Семантика task задана одинаковым уже подтверждённым task_spec; это проверка исполнения, не самостоятельного понимания задания или выбора модели.

Для обучения и scoring используются только fit/validation строки, control не оценивается; известная validation не является независимым подтверждением переноса. Техническое уточнение после запуска: pandas читает CSV целиком, затем сохраняются только эти две разрешённые части; контрольные labels не используются для обучения, выбора или метрик. Сравниваются RMSE/Macro F1, полные predictions/probabilities, число/расписание итераций и serialize/reload identity, стоимость. Численное совпадение сузит причину до непроверенных путей/выбора/настроек платформы, но не докажет равенство всех методов или полных запусков. Любые ошибки/timeout сохраняются; новые API calls отсутствуют. Production ZIP/зависимости не меняются.
