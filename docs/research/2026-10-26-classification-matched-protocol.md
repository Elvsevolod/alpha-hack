# До запуска: сопоставимые деревья и автономный агент на классификации

Последний live classification результат агента0,620099 и авторские деревья0,653630 имели разные контрольные наборы (14 397 и17 141 строка), поэтому численное ранжирование между ними не установлено. Цель нового опыта — измерить фиксированную сильную процедуру на точных строках агентского разбиения и затем проверить текущего агента. Это не новый blind holdout и не новая авторская NN-серия.

ТЗ вновь сверено: UNSW-NB15, attack_cat из десяти классов, главная Macro F1, labels в CSV. Колонки label иattack не могут быть предикторами; времена/ID не превращаются в ключи для извлечения labels. Только предоставленные данные и разрешённые зависимости. Контроль уже использовался прошлым live run и может пересекаться с development других серий; независимого переноса не заявляется.

Порядок заранее фиксируется: сначала offline reference, после terminal — один новый Qwen-run. Результат первого не используется для изменения второго. Оба имеют верхние пределы900s wall, CPU1,3072MiB. Native development, не официальная Linux/8CPU/32GB/3h среда. Human development фиксированного рецепта не входит в900s и не скрывается; это сравнение уже существующей модели с ограниченной автономной процедурой, не равные бюджеты разработки.

Reference: неизменённый trees arm из frozen author study — current_weighted XGBoost cap589/depth5/lr0,06 и hierarchy_balanced LightGBM gate757/attack304/lr0,05/leaves31. Используются только параметры/структура и клонируемые preprocessors из templates; модели обучаются заново. Target-free network features, веса/correction, uniform blend и decision procedure сохраняются точно по существующему audited коду. Параметры, веса ансамбля и пространство decision не меняются после просмотра. Outer split берётся из старого agent journal:fit56 974/validation16 299/control14 397. Для control модель fresh fit наsorted(fit+validation); independent inner calibration использует exact-feature groups. Выбор raw vs offsets и сами offsets учатся внутри разрешённого train, без control labels. Модели/serialization/inference/decision входят в900s. Проверяются hashes/splits и вероятности/classes/метрика.

Agent: текущий runtime после compact iteration feedback и native batch decoding,900s/CPU1/3072MiB/max-calls16/max-candidates4/seed42. Никакие модель, class_weight, признаки, recipe, research_focus или reference результаты в контекст не подставляются. Это отличается от прежних12 calls/2 candidates и предыдущего runtime, поэтому before/after не является причинным A/B отдельного исправления. Сравнение с reference признаётся matched только после проверки source_hash, множеств actual fit/validation/control и class/output contract. При несовпадении сравнение помечается несопоставимым, а не подгоняется после метрик.

Перед каждой фазой проверяются live процессы; чужие серии не останавливаются, фазы не идут параллельно. Для реального Qwen применяется alpha-api-limits непосредственно before и after terminal child, раздельные снимки/остаток/расход без ключей. Источники неизменны от freeze до terminal; offline reference не требует organizer API check. Оба outcome сохраняются, включая ошибки/timeout и всю стоимость. Субъективная полезность baseline/успех интеграции/качество/самостоятельный выбор различаются. Отсутствие PyTorch не объявляется доказанным осознанным отказом; его отрицательные фиксированные результаты не меняются.
