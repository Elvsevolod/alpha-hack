# Локальный бюджет обращений был потерян в контексте Qwen

## Подтверждённое расхождение

В [живом прогоне на 0b598ad](2026-10-26-autonomy-postfix.md) стояли пределы 6 model calls и 2 research candidates. Перед шестым обращением wire JSON показывал `counters.calls = 5`, но не содержал этих пределов или остатка обращений. Во всех шести фактически отправленных запросах отсутствовали `qwen_calls` / `max_calls`; это проверено по messages, а не только по compact summary. `Budget.snapshot()` возвращает остатки, но новая compressed-context ветка публиковала только использованные счётчики. После чтений и preview модель не могла из своего контекста определить, что шестая генерация исчерпывает локальный лимит.

Это подтверждённая потеря данных на границе Budget → ContextMemory → protected core. Она не доказывает единственную причину нулевого числа исследовательских кандидатов: решения модели, обрезанный ответ, лимит стенда и содержимое других материалов также влияют. Отсутствие прогресса нельзя целиком объяснять невидимым бюджетом без нового живого сравнения. В `4c39419` owning sources этой ветки ещё не менялись; новых live calls для воспроизведения не делалось.

Перед этим этапом сверены исходные `Budget.claim_call/snapshot`, `critic.review_candidate`, создание/сжатие/регистрация контекста, README независимого compressor и предыдущий фактический wire. Обоснование — требования ТЗ к автономному планированию гипотез и экспериментов (с. 5, 11–14), полному времени/ресурсам (с. 7). Карта первичных источников: [аудит](2026-10-26-agent-path-audit.md). Новая квота или обязательное направление поиска ТЗ не требуются.

## Изменение

`decision_context.resource_budget` берёт подтверждённые значения из того же Budget, который ограничивает исполнение. `ContextMemory` передаёт их через новый необязательный аргумент `configure(..., budget_state=...)`; compressor сохраняет JSON-словарь до 1024 UTF-8 bytes как `policies_resources.budget` внутри защищённого core. Типичный проверенный блок занимает 624 bytes. Прежние размеры всего core и каждого его раздела не увеличивались.

Передаются локальный предел и остаток model calls на момент снимка, остаток после **одной** генерации, предел/остаток кандидатов, локальный предел LLM-времени и уже использованное время. Дополнительно передаются условная стоимость одного uncached critic call, его порог из owning constant и признак disabled. Дешёвые native fits и готовые reviews могут не требовать дополнительной генерации; агенту не внушается правило «любое обучение требует два обращения».

`null` означает отсутствие заданного локального предела, а не нулевой остаток и не проверенную неограниченность провайдера. Данные API `/key/info`, ключи и текущий денежный/прокси остаток в runtime не добавлялись.

Блок относится к **неизменяемому decision snapshot**. Он не называется текущим балансом после произвольного числа попыток: transport retries могут расходовать дополнительные calls, пока тот же snapshot сохраняется; автоматически при prepare обновляется только remaining_seconds. После следующего решения новый snapshot получает текущие счётчики. Это явно указано в поле scope и README. Попытки не получают новую квоту, а реальный Budget по-прежнему проверяется перед каждым запросом. Per-attempt обновление точного остатка поверх immutable snapshot этим этапом не добавлено.

Логика запуска кандидатов, critic admission, исходный deadline, CPU/RAM, модель, гиперпараметры и рецепт ML не меняются. Не вводятся production max_calls/max_candidates: при незаданных пределах они остаются `None`. Проекция не резервирует и не списывает calls сама. При восстановлении используются сохранённые лимиты исходного Budget, а не вновь переданные CLI allowance.

## Проверки и границы

На исходнике до исправления **4 failed**: у native/JSON, последующего снимка и незаданных caps отсутствует `policies_resources.budget`. После изменения связанный набор **35 passed**, включая context integration и preview→apply через реальных workers. Финальный адресный набор — **6 passed**, 27,91 s — дополняет проверки native/JSON × 4 compaction stages, изменения счётчиков, null caps и resume проверкой, что замена budget в wire с пересчитанным request hash отклоняется checksum неизменяемого snapshot до регистрации/отправки. Counts и hashes: [ledger](../../research/context_resource_budget_20261026/summary.json); raw XML — ignored outputs/context_resource_budget_20261026. Перекрывающиеся наборы не суммируются.

Это исправление полноты подтверждённой информации для решения. Оно не доказывает, что реальный Qwen теперь выберет полезный эксперимент, уменьшит число чтений или улучшит RMSE/Macro F1. Новая живая проверка ещё нужна, в том числе с достаточным бюджетом для исследования; шестизапросный стенд не подменяет официальный трёхчасовой запуск. Исходные данные и уже открытые контрольные области не переименовываются в новые слепые данные.

Реальных organizer/Qwen API calls на этом этапе **0**; alpha-api-limits для этих офлайн-проверок не требуется. Предыдущий before/after относится только к своему завершённому прогону, а не выдаётся за текущий баланс. PyTorch и production/ZIP не расширялись. Авторский отрицательный результат RealMLP-TD-S, отсутствие подтверждённого прироста качества и общая активная цель сохраняются.
