## Что показало чтение AIDE

Скачан полный shallow clone в `outputs/agent-source-research/aideml`, коммит **ad73d227af481bea3de06f884f41b2993dd6453a**. Ничего из него не исполнялось.

[agent.py](https://github.com/WecoAI/aideml/blob/ad73d227af481bea3de06f884f41b2993dd6453a/aide/agent.py) выбирает draft до заданного количества стартовых решений, затем может выбрать debug по вероятности либо улучшать лучший успешный узел. Это дерево с простой эвристикой; называть эту конкретную политику MCTS неправильно.

Контекст improve включает задачу, сводку накопленного опыта и код выбранного родителя; запрашивается одна локальная модификация. Раздельные draft/debug/improve уже концептуально присутствуют в нашем `search_action`, родительских связях и проверках эффективного diff. Польза для нас — явное отображение текущей ветки и её результата в контексте, а не переименование существующих действий.

Есть два существенных различия. Во-первых, просмотренные draft/improve-инструкции прямо исключают предложение EDA. Это не соответствует нашей цели содержательной автономной разведки. Во-вторых, feedback-модель читает код/лог и возвращает найденную метрику. У нас следует сохранить числовую оценку контроллером, фиксированный контракт и независимость контрольных меток. Не стоит превращать вывод LLM о логе в источник истины о качестве.

[journal.py](https://github.com/WecoAI/aideml/blob/ad73d227af481bea3de06f884f41b2993dd6453a/aide/journal.py) хранит план, код, parent/children, ошибки, анализ и метрику. `generate_summary` передаёт дизайн, результат и validation metric успешных технически узлов, по умолчанию без полного кода. Это хороший образец компактной памяти опытов. Низкий скор технически успешного опыта тоже может попасть в такую сводку; нельзя утверждать, что AIDE хранит только положительные улучшения. Технически ошибочные ветки передаются отдельно при debug.

У нас уже есть журнал, короткие карточки и полные чтения. Следующее улучшение — доступная моделью запись «какой дизайн проверен → какое измерение получено → почему ветка сохранена/отклонена → когда к ней вернуться», со scope и происхождением. Приоритет этой записи должен зависеть от текущего вопроса.

## Что показало чтение MLZero

Скачан полный shallow clone в `outputs/agent-source-research/autogluon-assistant`, коммит **f228cd7028e197750391c02d94afcb7eea8da5ff**. Установка/запуск не выполнялись.

[NodeManager](https://github.com/autogluon/autogluon-assistant/blob/f228cd7028e197750391c02d94afcb7eea8da5ff/src/autogluon/assistant/managers/node_manager.py) хранит граф исследования, код, stdout/stderr, время, анализ ошибки, tutorial, validation score и отдельные счётчики валидированных, невалидированных и ошибочных посещений. Есть UCT/MCTS-выбор. Разделение технического исполнения и наличия валидированной метрики применимо к нашему сравнению; большая схема поиска требует самостоятельного испытания в бюджете.

[PythonCoderPrompt](https://github.com/autogluon/autogluon-assistant/blob/f228cd7028e197750391c02d94afcb7eea8da5ff/src/autogluon/assistant/prompts/python_coder_prompt.py) собирается из задачи, структуры данных, выбранного инструмента, предыдущего кода для improve/debug, ошибок и tutorial. Контекст ориентирован на выполняемую роль. Для нас это основание подгружать специфичный интерфейс/руководство по выбранной операции, вместо повторения всех тонкостей адаптеров в постоянном SYSTEM. Проверки соответствия строк и колонок прогноза полезны, но у нас должны оставаться исполняемыми гарантиями Publisher, а не только пожеланием в промпте.

[DataPerceptionAgent](https://github.com/autogluon/autogluon-assistant/blob/f228cd7028e197750391c02d94afcb7eea8da5ff/src/autogluon/assistant/agents/data_perception_agent.py) использует LLM для генерации/выполнения кода чтения файлов. Для наших CSV и подтверждённых ролей уже имеющийся ограниченный profiler обеспечивает более проверяемые числовые факты без дополнительной генерации на каждое чтение. Возможное преимущество их подхода для более широких модальностей не измерялось.

## Что взять в наше решение

1. **Контекст выбранной ветки и память результата.** Сохранять текущий вопрос, проверенный дизайн, comparator, фактический результат, scope и ограничение вывода. Это продолжает предложенную после Pi проекцию последнего перехода и использует существующие records/research_note.
2. **Руководства под выбранную операцию.** Разделить постоянные гарантии, стартовое состояние и подробности инструмента. Перед удалением custom-интерфейса из SYSTEM обеспечить его настоящий публичный read route; наличие старого helper недостаточно.
3. **Несколько осмысленных веток вместо инерции лидера.** Агент может продолжить лидера, проверить альтернативное представление или исправить техническую ошибку. Приоритет зависит от вопроса и стоимости, без обязательной квоты draft, фиксированного списка моделей или одинакового числа анализов.
4. **Проверяемая оценка исследования.** Зафиксировать исходный код/промпт/задачу, трассу действий, использование предыдущего результата, все расходы и финальную метрику. Не оценивать новую политику только её собственным объяснением. Для одинаковых сохранённых переходов сначала провести офлайн-проверки доставки, затем отдельную Qwen-серию на новых задачах.

Часть механизмов у нас уже есть. Поэтому первое внедрение — улучшить доступность и композицию текущего состояния. Новый оркестратор, несколько постоянно вызываемых LLM-ролей или полный MCTS пока не обоснованы замерами пользы.

## Границы переноса

Все скачанные проекты остаются материалами разработки и игнорируются Git. Они не включены в конкурсный ZIP, их окружения не устанавливались, API не вызывались. В solve остаются Qwen организаторов, данные текущей задачи, разрешённые библиотеки и доставленный локальный корпус. Закрытые метки, общий дедлайн, worker и проверенный резерв CSV сохраняются.

Готового проекта, соответствие которого всем нашим ограничениям было бы подтверждено, в этой проверке не установлено. Найдены близкие системы и конкретные механизмы для адаптации. Рост балла после их переноса пока не измерен. [Зафиксированные версии и исходные файлы](2026-10-25-related-ml-agents-evidence.json) позволяют повторить чтение.
