# Однократно закодированный массив кандидатов в native-ответе

В [последнем реальном опыте](2026-10-26-autonomy-regression-expanded-result.md) один из четырёх аргументных отказов — BatchArgs.candidates пришёл строкой, содержащей JSON-массив. До этого native parser уже однократно декодировал аналогичные строки для объявленных pipeline/hypothesis/source, но не массива candidates. Предложенный пакет отклонялся до обучения и требовал нового решения Qwen.

Добавлена только нормализация представления: для native run_experiments, если подтверждённая schema объявляет candidates массивом, строка разбирается один раз строгим JSON decoder и должна дать list. Сохраняются значения, порядок и число кандидатов. Дальше работают прежние BatchArgs bounds2–4, TrainArgs, preflight каждого member, ограничения engines/параметров/ресурсов, evidence, distinct recipes, бюджеты и обычный sequential dispatcher. JSON transport, ids, пропущенные значения, ссылки и другие поля не исправляются. Никакого выбора модели или автоматического повторного API-запроса это изменение не делает.

Общий строгий JSON decoder выделен из прежнего object helper. Дубликаты ключей, NaN/Infinity, хвостовой текст и неполный JSON остаются запрещены; дважды закодированный массив не распаковывается повторно. Неверный тип вместо массива отклоняется. Тесты подтверждают, что неверный второй кандидат (engine, evidence или дубликат рецепта) не допускает даже первый fit и не изменяет опубликованный CSV/control/candidate_count.

После корректировки тестового harness (Command использует as_dict(), а не arguments attribute) before_corrected_harness.xml:8 failed/3 passed. Это одна недостающая нормализация и новые проверки её строгих границ, а не восемь независимых эксплуатационных дефектов. Первоначальные XML с ошибкой harness сохранены и не считаются доказательством дефекта runtime. После исправления с pressure transport и reference-repair tests:22 passed, after_corrected_harness.xml. Финальная расширенная матрица:14 passed, final_boundaries.xml. Наборы пересекаются.

HTTP mock проверяет полный действующий путь QwenClient→compressed response→Controller batch dispatch: один запрос, два разных ridge alpha17/29, ровно два sentinel execute, без изменения CSV. Fixture реально обучает стартовый baseline; два research-fit заменены sentinels. Это проверка исполнения формата, не самостоятельный выбор настоящей Qwen и не измеренный выигрыш wall/качества. Число кандидатов и бюджеты при декодировании не увеличены.

Два других реальных отказа read pipeline без IDs и неподтверждённая evidence identity остаются корректными отказами. Код parser не удаляет валидные ids; для воспроизводимых native/JSON чтений они сохраняются. Полный исходный provider body ошибочных ответов в этом native run не сохранялся, поэтому индивидуальные ответы нельзя восстановить и выдать за точный raw-response replay. Тесты воспроизводят наблюдённый класс кодирования и проверяют текущий путь независимо.

Все новые проверки офлайн, API организаторов не использовался. Исторические12 ответов/четыре отказа/549,71s не пересчитываются задним числом. Изменение улучшает переносимость существующего пакетного интерфейса, но не доказывает прирост RMSE/MacroF1 и не заменяет работу над качеством выбора экспериментов. Production ZIP/зависимости/PyTorch не расширялись.
