Общий ML-аудит продолжается. Основание — требования самостоятельного исследования, исполнения выбранных настроек и соблюдения бюджета, сопоставленные с первичными материалами в `2026-10-26-agent-path-audit.md`. Новое семейство моделей не добавляется; параметры по control не выбираются.

## Наблюдение в реальной трассе

Исторический `adult_A / exp_f17651f5e870d406 / smoke` прочитан без запуска и изменения исходных файлов. Единственный Optuna trial выбрал `subsample=0.7467983561008608`; положительная `subsample_freq` отсутствовала. Контракт исполнителя уже запрещает такую неработающую настройку bagging. Trial завершился `failed`, worker вернул только `ValueError: Optuna completed no valid inner trial`, score отсутствует. Это объясняет конкретный отказ, а не доказывает, что этот HPO улучшил бы Adult.

В соседней ветке уже существовал коммит **4478c2e9f6f7445a3301be59862f387b1789d8ff**, `fix: report public recipe constraints for failed HPO trials`. Его изменения `tuning.py` и первые два теста перенесены выборочно. Это повторное использование исправления с указанием авторского источника, не новая находка и не слияние всей ветки.

## Дополнительный обрыв доставки

Два исходных теста проходили напрямую. Новый тест Controller → worker подтвердил, что публичная причина всё ещё исчезала: JSON-массив строк проходил через общий фильтр quoted values как `public recipe constraints=['<value>']`. До исправления этот тест упал именно на отсутствии `inactive_row_bagging`.

Сводка теперь соединяет доверенные причины проверки рецепта обычным текстом. Общий worker-фильтр не ослаблен. В trial history сохраняются публичные причины и тип исключения; произвольный текст backend exception в эту сводку не включается. Число причин и длина по-прежнему ограничены. Настройки не исправляются автоматически: агент должен осознанно прислать новый рецепт.

## Проверки и границы результата

Новый набор: **5 passed**. Проверены preflight без fit, отсутствие приватных feature/backend sentinel в публичной HPO-сводке, доставка причины через реальный worker/controller, а также два полных HTTP mock-цикла **native и JSON**. Mock выдаёт исправленный `subsample_freq=1` только при наличии фактически доставленного `inactive_row_bagging` в следующем запросе. Исправленный HPO выполняется; затем выбранный измеренный лидер проходит полный refit и публикует настоящий CSV на 25 строк. Победа HPO над baseline не является условием теста.

Связанный набор поиска, резерва selected fit, диагностик и сжатого контекста: **59 passed / 2 failed**. Оба отказа — `ModuleNotFoundError: autogluon` в неизменённом адаптере; AutoGluon отсутствует в локальной среде. Зависимости не добавлялись, эти два пути не считаются проверенными. Остальные тесты не повторялись ради получения зелёного счётчика.

Первый запуск расширенного набора дал 3 passed / 2 failed из-за запрета sandbox на bind локального mock-сервера. После разрешённого запуска с доступом к `127.0.0.1` обе проверки прошли. Это ограничение среды тестирования, не дефект алгоритма.

Источник, SHA-256 исторических файлов, заимствованный коммит, отрицательная проверка доставки и итоговые XML зафиксированы в `research/agent_path_audit_20261026/hpo_feedback.json`. Исторические обучающие строки, модели и секреты в свидетельство не копируются.

Реальных API-запросов организаторов — **0**; alpha-api-limits для этих offline-проверок не требуется. HTTP mock задаёт детерминированную политику и не подтверждает самостоятельное исправление настоящим Qwen. Прирост RMSE/Macro F1 не заявляется. Main, конкурсный ZIP и чужие серии не менялись; PyTorch остаётся экспериментальной возможностью без расширения production-интеграции. Общая цель остаётся активной: качество и автономный выбор на сопоставимой проверке ещё требуют подтверждения.
