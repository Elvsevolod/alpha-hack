# AutoGluon: редкий класс исчезал до Macro F1 и полного refit

Продолжение: прежний отказ для нового объявленного класса заменён [фиксированным native refit без нового поиска](2026-10-26-autogluon-new-class-refit.md). Ниже сохранён отчёт об исходном исправлении c3dd300.

ТЗ многоклассовой задачи организаторов прямо связывает выбор Macro F1 с редкими Worms, Shellcode и Analysis. Поэтому незаявленное удаление наблюдавшегося класса внутри AutoML — существенное расхождение исследуемого рецепта и фактического обучения, даже если доля удалённых строк мала.

На исходниках `46c6832` настоящий AutoGluon 1.3.1 в синтетическом Macro F1-сценарии удалил редкий класс. Из 1000 разрешённых строк пять имели редкую метку; inner split содержал три таких строки из 700. Native LightGBM фактически получил **697** строк вместо 700, затем **995** вместо 1000 при заявленном full refit. Внутренняя карта классов стала `{A:0, B:1}`. До исправления воспроизводящий тест упал.

Причина — стандартный label_count_threshold=10 в DefaultLearner. Порог может сохраняться, если удаление затрагивает менее 2.5% строк и остаются два класса. Для Macro F1 такой процент не означает малой потери. Наши training_keys и rows=len(X) описывали исходную популяцию, но не свидетельствовали о количестве строк native fit.

Исправление устанавливает label_count_threshold=1 и для первоначального predictor, и для fresh bagging/stacking replay. После fit проверяется сохранение всех **наблюдавшихся** меток. Не требуется искусственно добавлять отсутствовавший в разрешённом fit класс из TaskSpec. Native bagging требует минимум два наблюдения каждого класса; singleton теперь отклоняется до создания predictor с явным маршрутом selection/direct, без удаления или дублирования строки.

Отдельная проверка frozen selection refit останавливает выполнение, если transform_labels возвращает NaN для нового разрешённого класса. Преобразование меток не доходит до native fit, исходный predictor и его предсказания сохраняются. Это честное ограничение, **не поддержка расширения словаря при refit**. Полное обучение такого случая остаётся открытой задачей; новая модель с пересозданным label space потребует отдельной проверки фиксированного рецепта и отсутствия нового подбора. Контроллер уже сохраняет CSV контрольной модели при ошибке refit; новый guard не заявляется сертификатом всего пути Controller для этого случая.

Публичная схема описывает эти границы, registry version 6 обновляет кэш совместимости. Direct/Optuna, PyTorch, требования зависимостей и ZIP не расширялись. Старые обученные артефакты не переписывались.

## Проверки

- До исправления: **1 failed**, история реальных native fits — 697 / 995 строк, редких меток нет.
- Selection после исправления: **700 / 1000 / 1200** строк, в full fit/refit сохранены 5 / 6 редких меток, NaN-меток нет.
- Реальные selection, bagging, stacking: словарь из трёх классов сохранён, fresh full refit использует все 1200 строк, вероятности приведены к подтверждённому порядку TaskSpec, редкому классу не присваивается нулевая вероятность по причине удаления.
- Singleton bagging/stacking: отказ до native predictor. Новый класс при selection refit: отказ до третьего native fit, оригинал не изменён.
- Финальный связанный набор: **32 passed**, включая шесть новых сценариев, прежние iteration aliases, weight boundary, full-row/iteration refit, exact-group bagging/stacking replay и reference memory/cache. Это один набор корректности, не 32 независимых подтверждения качества. Промежуточная ошибка fixture — отсутствовал task в predict context; исправлена без изменения runtime, отрицательный XML сохранён.

Это синтетический tripwire с 0.5% редкого класса и специальным признаком-индикатором для проверки вероятностей, а не доказательство качества или отсутствие утечки в реальных данных. Дополнительные seeds не использовались как независимые подтверждения. Organizer control не переоткрывался. Улучшение Macro F1/RMSE, полная стоимость запуска и самостоятельный выбор Qwen не измерялись.

Среда — native Python 3.12, изолированные AutoGluon packages 1.3.1 и setuptools 75.8.2, LightGBM 4.6.0; полный конкурсный Linux runtime не сертифицирован. Реальных organizer/Qwen API calls **0**; alpha-api-limits для чисто офлайн-серии не требуется. Другие серии не перезапускались и не останавливались.

Проверка seed GBM, с которой начинался аудит, дефекта не выявила: pinned LGBModel переводит переданный seed_value в native seed. Остальные семейства этим наблюдением не сертифицируются.
