# Аудит агента после сверки с ТЗ

Поручение расширено пользователем: продолжать ML/DL и искать потери данных/параметров и ошибки исполнения, прежде чем добавлять возможности сверяться с задачей и ТЗ. Текущая замороженная серия не изменяется. Новые исправления и их испытания отделяются от её исходного состояния.

## Основание

Прочитано исходное `Альфа Хак_AutoML .pdf`, 20 страниц, оба `task.md`, baseline и реестр уточнений организаторов `skills/alpha-submission-zip/references/submission-requirements-2026-10-21.md`.

| Требование | Первичный источник | Что проверять в коде |
|---|---|---|
| От описания до CSV, самостоятельные гипотезы/эксперименты/выбор | ТЗ с. 5, 11–14 | Семантический контракт → tool args → effective recipe → worker → feedback → selection |
| Один код для неизвестных задач | ТЗ с. 5, 16 | Роли столбцов, метрика, классы и output определяются контрактом; нет dataset-specific production branches |
| Python 3.12, 8 CPU / 32 GB / 3 ч | ТЗ с. 7 | Весь граф, startup, дополнительные fit, финальный refit/inference/publication и резерв |
| Только разрешённые зависимости, case data; без pretrained weights и внешнего интернета | ТЗ с. 7, уточнения организаторов | Registry, custom dependency guard, worker environment и отсутствие downloads/install |
| Нейросети допустимы, если укладываются в ограничения | ТЗ с. 8 | DL — проверяемая опция, а не обязательное направление; качество и стоимость важнее наличия PyTorch |
| Собственная валидация, никакого скрытого промежуточного score | ТЗ с. 17 | Fit-only preprocessing/decisions, protected control, refit без подбора по control |
| Регрессия: RMSE исходной шкалы | Task энергопотребления | Погода известна за тот же год; Year_Factor не календарный год, id не доказанный building ID |
| Классификация: Macro F1 десяти атак, строки в исходном порядке | Task UNSW-NB15 | Class order, probabilities vs decisions, rare-class support, ID/order in publication; `label` не восстанавливать |

Проверка metadata и стоимости обоснована этими требованиями. Развёртывание сервиса и production-monitoring ТЗ не требует (с. 12). Нельзя подменять автономность предписанным вручную победителем или техническим mock.

## Проверяемые риски

1. Числовой физический dtype при категориальной роли: сохраняется ли роль в общем preprocessing, включая новый производный столбец? CSV reader обычно сохраняет категории строками, но dataframe/custom/related-table пути могут передать числа.
2. Fixed worker initialization: остаётся ли startup фиксированным при прогнозировании большего fit без полного набора phase timings?
3. OOF cache: проверяется ли request identity для успешного результата так же строго, как для terminal failure, и не может ли корректный hash чужого результата скрыть неверную provenance?
4. Порядок и пространство классов/строк: проходят ли они через worker serialization, OOF composition и конечный CSV без перестановки смысла?
5. Сжатие и feedback: остаются ли recipe identity, bounded errors, объём признаков, auxiliary fits и фактическая основная метрика доступны модели?

Это список гипотез аудита, не перечень уже доказанных дефектов. Каждый фикс требует минимального воспроизведения, проверки влияния и регрессии. Во время последовательных измерений heavy training-тесты не запускаются параллельно.

## Подтверждённые исправления

`tests/test_agent_path_audit.py` до исправлений: 6/6 воспроизведений упали. После исправлений и расширения типов/ветвей: совместно с phase scaling и известными исходами OOF **34 passed** (`outputs/agent_path_audit_checks.xml`).

| Дефект | Последствие | Исправление |
|---|---|---|
| `FeatureMatrix` выбирал категориальный канал только по dtype | Подтверждённый числовой код категории воспринимался как непрерывная координата | Подтверждённая роль имеет приоритет; float/nullable Int64, encoded/native пути и неизвестная категория проверены. Object-приведение перед missing/model category fill сохраняет nullable numeric входы |
| Fallback прогноза при отсутствии полного phase ledger масштабировал initialization вместе со строками | Startup 3 с при ×10 строк давал +37,5 с с запасом вместо +3,75 с; агент мог отказывать доступной модели | Initialization добавляется после масштабирования fit. Старый fallback без измеренного initialization сохраняет поведение |
| Успешный `cached_oof` возвращался до проверки request/context/rows | Верный SHA самого файла не подтверждал, что он относится к текущему pipeline/task/protocol | Общая проверка identity выполняется до completed-path; проверяется request digest, если он записан worker. Несовпадение даёт `outcome_unknown`, без нового fit и без изменения файлов |

Эти исправления не демонстрируют прирост RMSE/F1 сами по себе. В public CSV категориальные поля обычно уже строки; дефект затрагивал иные корректные dataframe-пути, важные для универсальности.

Сверены и уже имеющиеся защиты: LightGBM получает positional safe aliases для специальных символов в названиях; полная recipe доступна через `read_run_records(view=pipeline)` и versioned source; сжатая запись сохраняет метрику, score, wall time, peak memory и ссылку на полное описание; `Publisher` выравнивает row keys и class order, проверяет CSV round-trip и атомарно сохраняет ответ. Для этих мест новый фикс без воспроизведения не добавлялся.

Аудитные проверки занимали около секунды каждая, без обучения моделей, во время последовательной авторской серии. Поэтому хост не объявляется полностью изолированным. Код авторского learner/driver и замороженные параметры не изменялись; изменения общего preprocessing/cache/forecast не используются исследовательским `Classical`/`RealMLPTDS` путём.
