# Отбор признаков: доставка информации и покрытие направлений

Проверены все12 сохранённых запросов последнего автономного regression run. Во всех compaction stage0, ровно62 столбца profile.columns, omitted_columns=0; множество совпадает с подтверждённым feature_columns полного task-контракта. Наличие пропусков/новых категорий и risk_flags также передавалось. Поэтому отсутствие feature ablation в этом опыте нельзя объяснить потерей названий признаков при сжатии. Статистический профиль не равен семантическому описанию: словарь и task text остаются читаемыми источниками, а свидетельства их полноценного использования агентом не получены.

При этом research_options перечислял AutoML/shift/composition/history/related tables, но не учитывал отбор признаков как отдельное направление. В direction_map структурный hash поднабора уже различался; проблема относилась к обзорному учёту coverage, а не к отсутствию include_features/exclude_features в интерфейсе.

Добавлена необязательная строка feature_subset. Она учитывает только эффективный непустой строгий поднабор подтверждённых предикторов, вычисленный тем же selected_features, что применяет preprocessing. Явный полный список столбцов не засчитывается как проверка поднабора. Завершённый непилотный результат отмечается measured; timeout/unknown — technical_failure; пилот не считается качественным сравнением. При единственном предикторе пустой поднабор не предлагается. Самих столбцов, готового рецепта и автоисполняемой карточки изменение не создаёт. Подсказка предлагает обоснованную задачей групповую абляцию при наличии transfer/residual evidence, сохранение структурных ролей и остальных модельных решений для атрибуции; обязательной квоты нет.

Выявлен отдельный дефект: branch coverage считал completed records от прежнего validation_hash, хотя direction_map уже фильтровал их по активному протоколу. Это могло представлять метод как проверенный после пересмотра разбиения. Добавлена такая же фильтрация measurements. Предложения с известным другим operation.protocol_hash тоже исключаются; отсутствие protocol_hash не превращает предложение в измеренный результат.

До/после на неизменённом synthetic record со старым split: исходный research_options из9c22b95 показывал Optuna measured/1, исправленный — no_admitted_attempt/0. Source replay загружен из Git в отдельном процессе, без изменения основного runtime и без обучения/меток. Это подтверждение ошибки учёта, а не новый эксперимент качества.

Проверки:25 passed за100,87s, outputs/feature_subset_coverage_20261026/after.xml. Они включают различие непустого поднабора и полного списка, pilot/technical/current/old protocol, известное старое предложение, single-feature отказ и реальный Controller/public read в native/JSON на всех четырёх стадиях сжатия; compact summary остаётся≤3072 bytes. Связанные parent inheritance/finish проверки проходят: новая строка не вводит обязательный fit и не открывает контроль. После уточнения текста scope:10 целевых проверок passed за5,31s, final.xml; это пересекающийся набор, не ещё10 независимых проверок.
