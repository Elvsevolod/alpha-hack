# Готовый ансамбль: прогноз требовал уже ненужную подготовку потомков

## Подтверждённое расхождение

Аудит начал с диска и защиты зависимостей: финализация должна сохранять необходимые модели, но не резервировать повторное исполнение уже готовой работы. На `e6241f5` нашлось расхождение estimate и Controller._prepare_finalist. Исполнитель сразу возвращал проверенный prepared ensemble, а прогноз проходил через всех участников и начислял их fit/disk, даже если ансамбль уже содержал самостоятельные control/test predictions.

В контролируемом unit-ledger это давало **10.4 s дополнительного fit и 100 bytes** для двух синтетических прототипов вместо нуля. Эти числа — fixture-значения, не ускорение настоящей ML-задачи. До исправления **3 failed / 3 passed**. Такое завышение могло исключать доступный ансамбль из финалистов или без необходимости требовать освобождения диска; фактический ущерб конкурсному качеству не измерен.

## Исправление

estimate сначала проверяет полный объявленный DAG на циклы и успешные исходные записи. Затем обходит только необходимую работу сверху вниз. Узел с совпавшими frozen recipe / row hash / artifact hashes становится границей для подготовки текущей фазы. Для него не вычисляется новый model-fit forecast и не сканируются source model files. Если участник запрошен отдельным финалистом или нужен другой неготовой ветке, он включается один раз. Iterable корней материализуется до повторных обходов.

Неготовый, изменённый, повреждённый или относящийся к другим rows/recipe cache границу не создаёт. Будущий refit в другой фазе также требует полного графа, если собственного ready-result у него нет. Closure для защиты артефактов не сокращается: cleanup.protected_ids продолжает сохранять все исходные зависимости. Логика cleanup не менялась.

Ноль означает **отсутствие оставшегося обучения и дополнительного выделения диска**, а не нулевую wall latency. Hash verification готового результата остаётся; повторная проверка крупных артефактов и её I/O-стоимость этим этапом не оптимизировались. Критерий готовности не расширялся: сохранены прежние проверки идентичности и хешей; не заявляется новая сертификация полноты произвольно созданных manifests.

## Проверки

- Готовый root, отдельный child-root, общая зависимость, iterable roots, испорченные hash/rows/recipe; готовый узел не вызывает measured_cost.
- Проверено, что прерванный текущий обход не скрывает цикл и не снимает защиту прототипов; другая фаза по-прежнему требует потомков.
- Настоящий Controller: два Ridge → uniform ensemble → frozen plan → контрольная подготовка. Промежуточные control-каталоги участников перемещены в test-only retired-каталог, исходные прототипы сохранены. Root-cache повторно используется без подготовки участников. Затем controller один раз открывает control, выполняет ровно два full-refit worker на всех train-строках и публикует правильный CSV на 25 test-строках с сохранением ID. Финалист закреплён технической fixture, поэтому самостоятельный выбор и превосходство ансамбля не заявляются.
- Итоговый связанный набор **61 passed**: новые сценарии, canonical recipe identity, budget finalization, cleanup protection, final boundaries, class-work и прежнее фазовое масштабирование. Отдельные промежуточные наборы пересекаются с ним и не суммируются.

Task/CSV требования, метрики, сами ML-рецепты, веса смеси и PyTorch не менялись. Это исправление согласованности планирования и исполнения, не новый optimizer и не доказательство RMSE/Macro F1 gain. Диск при class expansion и влияние предыдущей консервативной class-work поправки на выбор полезных кандидатов остаются открытыми проверками.

Реальных organizer/Qwen API calls: **0**, alpha-api-limits для офлайн-тестов не требуется. Конкурсный ZIP, исходные данные и чужие серии не менялись. Полный Linux/3h run и реальная автономность остаются неподтверждёнными. Общая цель активна.
