# Реализация стартового контекста и модульного промпта

Дата: 2026-10-25. Ветка `feat/strong-reference-search`, база `b5eb54f`. Реализовано предложение из [исследования Pi и других агентов](2026-10-25-agent-context-architecture.md). Исходники Pi остаются только в игнорируемом исследовательском каталоге; зависимости и код Pi в конкурсный runtime не добавлялись.

## Изменения и основания

| Проблема / требование | Реализация | Проверка |
|---|---|---|
| SYSTEM смешивал постоянные гарантии и подробные интерфейсы | `automl_agent/prompting.py`: пять отдельных системных секций; подробные правила доставляются по запросу | Оба транспорта, неизменность 17 действий, замер фактического framing |
| После удаления INTERFACE из SYSTEM модель могла потерять его | Версионированные run sources для candidate_interface, runtime_guidance и research_policy; публичный каталог с точными маршрутами чтения | Полное побайтовое восстановление интерфейса и политики через continuations на всех четырёх уровнях сжатия |
| В начале автоматически подбирались материалы без исследовательского вопроса | Явный пакет `deferred` с пустым materials; выбор включается при активной заметке или гипотезе. Ручной поиск доступен всегда | HTTP-имитация читает каталог и следующую страницу; аудитор проверяет даже отложенный пакет |
| Последний переход распределён по нескольким частям состояния | `decision_frame` версии 1: идентичность операции, её статус/исход, статус анализа и связь с текущим протоколом; отклонённый запрос указан отдельно | Следующий запрос действительно получает результат предыдущей команды; значения таргетов/прогнозы не копируются |
| Новый формат не должен вытеснять прежние обязательные сведения | Общая функция `project_work` используется и для подсчёта размера, и для формирования защищённого ядра. При тесном бюджете остаётся ссылка на полный frame | Проверки давления контекста; прежние CORE_LIMITS не увеличивались |
| Старые запуски должны сохранять своё поведение | Промпт и тела руководств закрепляются в журнале с версиями и хешами. Запуски без новой метаинформации принимают legacy-профиль | Восстановление legacy и новой сессии, защита от подмены текста, игнорирование случайного caller override |
| Смена способа подачи материалов не должна ломать восстановление памяти | Проекция завершённых операций отделена от выбора материалов и выполняется даже для `deferred` | Восстановление после сбоя без повторного обучения, команды или подтверждения доставки |
| Исторические записи неизменны | Порядок каталога детерминирован, ID записи каталога включает версию | До/после перезапуска каталог имеет тот же маршрут; старые версии не перезаписываются |
| Нужны проверяемые отчёты | Финальный report содержит версию промпта, system_hash, guides_hash и хеши секций. Событие привязки хранит только метаданные | Проверка отчёта; полный текст руководств в это поле не попадает |

Это наши инженерные решения. Ограничения организаторов — разрешённая модель и зависимости, данные текущей задачи, ресурсы, автономный цикл и корректный итоговый файл — остаются обязанностью исполнителя. В промпте явно отделена действующая classical-only политика проекта от требований организаторов. Новых ML-исполнителей, сетевого доступа, установки пакетов или дополнительного LLM-агента нет.

## Как теперь начинается исследование

Контроллер подтверждает задачу и публикует существующий резерв/опору по прежнему пути. Первый исследовательский запрос получает компактные правила, подтверждённый контракт, профиль, актуальные ресурсы и журнал результатов. Полные методические материалы не выбираются автоматически до появления вопроса.

`current_work.local_guides` ведёт к короткому каталогу: назначение руководства и точный read route. Чтение выполняется через имеющийся `read_run_records`, с прежними ограничениями области, версии и UTF-8 continuation. Если прямой маршрут не помещается в защищённый блок, каталог остаётся доступен через `list_run_records` с `filters.component=startup_guides`. Индексированный корпус знаний перестраивать не требуется.

После команды модель получает прежние наблюдения и дополнительно компактный factual frame. Вопрос, гипотеза и интерпретация остаются предположениями агента в существующей заметке/гипотезе. Frame не объявляет операцию успешным ML-экспериментом только потому, что инструмент вернул ответ. Статус неподтверждённого исхода не превращается в отрицательный результат модели.

Модель выбирает следующий полезный анализ, эксперимент или finish. Обязательная очередь инструментов, квота моделей и универсальный порог улучшения не добавлены. Полная переписка assistant/tool и платный summarizer не вводились: используется существующий детерминированный snapshot и журнал.

## Совместимость и восстановление

Новые сессии используют prompt version 2. В `llm_prompt_contract` сохраняются точный базовый системный текст и тела руководств с хешами. Повторное открытие использует эту сохранённую версию. Старая сессия без такого контракта получает version 1 с прежним SYSTEM, прежним автоматическим подбором материалов и без новых inline-полей. Транспортные инструкции и явно заданная разработческая цель добавляются при сборке; полный фактически отправленный запрос имеет отдельный hash в существующем аудите.

Отложенный подбор не отключает аудит и восстановление evidence memory. Ошибка целостности корпуса сохраняет статус `integrity_error`. Новые инструкции и ссылки не дают полномочий обходить TaskSpec, совместимость адаптеров, подавление обратной связи, контроль или резерв финализации.

Замороженный runtime прежнего коммита доступен для отката и сравнения. Несовместимый или повреждённый сохранённый prompt contract отклоняется, а не чинится молча.

## Приёмка

Проверки выполнялись офлайн, включая локальный HTTP и MockTransport. Для тестов с настоящим bind localhost понадобился выход из файловой песочницы; внешний API Qwen не вызывался.

Подтверждены доставка и продолжение страниц в native/JSON, сохранение ссылок после сжатия, отказ при потере пакета, восстановление сессии и памяти, учёт неизвестных исходов и исходного дедлайна. Существующий сценарий HTTP-имитации «обучить Ridge → finish → control/refit → CSV» прошёл в native, JSON и native со строковым кодированием вложенных объектов. Это проверка полного технического маршрута, а не готовности к конкурсу или качества самостоятельных решений Qwen.

Завершённые наборы перекрываются; их нельзя складывать в количество независимых тестов:

- 110 passed: standalone compressor, reference memory, Qwen stream/settings/unknown outcome;
- 56 passed, 14 deselected: новые контекстные контракты и существующие M1–M8-проверки, кроме M4 с отсутствующим историческим файлом;
- 30 passed: локальный HTTP/native/JSON, финализация и ранее найденные ошибки интерфейсов;
- 47 passed: доставка выбранных знаний, восстановление памяти, experiment review, проектный скилл и repair guidance;
- 8 passed: финальная адресная проверка перезапуска, полного чтения руководств, обоих транспортов и старой версии промпта.

Полный repository suite не заявляется: [ранее найденные исторические fixtures в outputs](2026-10-25-preprocessing-contract-audit.md) остаются отдельной проблемой. Их отсутствие не маскируется успешностью выбранных наборов.

С одинаковыми текущими 17 схемами и одним Transport, без пользовательского контекста:

| Профиль | Базовый system, UTF-8 bytes | Native overhead | JSON overhead |
|---|---:|---:|---:|
| Legacy | 13 515 | 62 066 | 38 304 |
| Layered | 4 268 | 52 680 | 28 918 |

Native overhead меньше на 9 386 bytes, примерно **15.1%**. Это не замер всего промпта, токенов провайдера или денежной экономии. Доставка подробных руководств по запросу тоже расходует модельные ходы; существующее чтение Source ограничено 768 bytes на страницу. На задачах с частым custom-кодом дополнительные чтения могут перевесить сокращение стартового текста. Этот риск должен входить в живое сравнение.

## Что пока не доказано

Реальная стоимость запросов, качество выбора следующих экспериментов и итоговые предсказания нового профиля на живом Qwen не измерялись. Короткий начальный текст может потребовать дополнительных чтений; потеря условий руководств или лишние чтения способны ухудшить результат. Следующая сравнительная серия должна проверять именно эти последствия на новых задачах, сохраняя модели, данные, протокол и бюджет сопоставимыми. Перед и после реального Qwen обязательны снимки лимитов.

В этой поставке не менялись признаки, обучающие алгоритмы, валидация и правила публикации CSV. Новый конкурсный ZIP не собирался.
