# Самостоятельный модуль базы знаний ML

Модуль разработан отдельно от `automl_agent`, `solution.py` и `context_compressor`. Он содержит сборщик официального корпуса, поиск, ограниченный контекст, содержательную память, проверочный контур и плоскую поставку. Впоследствии он подключён к архитектуре v016 в общем решении **v019** через `automl_agent/knowledge.py`; результаты и ограничения интеграции находятся в [отдельном отчёте](../outputs/knowledge_integration/REVIEW_AND_TESTS.md). Приёмка самостоятельного v003 ниже относится к первоначальному объёму работ и сохранена без переноса её результатов на объединённый архив.

**Текущая поставка:** `releases/ml_knowledge_v003.zip`. Это поставка блока для интеграции. Она не содержит `solution.py` и не предназначена для самостоятельной отправки на платформу.

**Граница готовности самостоятельного v003:** 46 технических тестов и новый набор проверки контекста проходят, но весь исходный план ещё не закрыт; историческая вспомогательная проверка достаточности пакетов даёт 32/40. В корпусе учтены 16 библиотек точных версий; остаются 400 неразрешённых элементов документации и зарегистрированные ошибки импорта отдельных модулей при извлечении API. Полнота корпуса не подтверждена. При отдельной разработке живые 24 запуска Qwen и проверка объединённого агента были отложены до интеграции; актуальные технические результаты v019 приведены в отчёте по ссылке выше. Подробнее об исходном блоке — `REPORT.md` и `ACCEPTANCE.json`.

## Состав

- `runtime.py` — `ReferenceStore`, `ReferenceArgs`, `REFERENCE_SCHEMA`; поиск FTS5 и резервный лексический индекс, проверка целостности, непрозрачные курсоры.
- `context.py` — автоматический подбор по подтверждённой задаче и агрегатам fit, пакеты до трёх материалов и 6000 символов, контроль окончательного запроса.
- `memory.py` — отдельный журнал фактов, рекомендаций, гипотез и результатов; зависимости от данных, валидации и пайплайна.
- `manifest.json` — единственный список 16 библиотек, точных версий и маршрутов получения. `requirements.txt` побайтно совпадает с файлом организаторов.
- `sources/` — закреплённые официальные снимки, исходные хеши, лицензии и экспорт точных установленных API. Доступ к сети нужен только при предварительном сборе.
- `frozen/` — окончательные нормализованные документы, перечень ожидаемых элементов, отчёт покрытия, входной lock и лицензии.
- `corpus/` — проверенная SQLite-база и lock; 31 675 документов, 32 методические карточки, 20 рецептов, восемь пространств параметров, один контракт ресурсов.
- `baseline/before.zip` — сохранённые до изменений исходники и старый корпус. `baseline/snapshot.json` содержит хеш каждого файла. Это снимок разработки, а не старый конкурсный кандидат.
- `evaluation/` — 40 исторических разработочных запросов, 30 новых разработочных и 30 отложенных, точные выдержки, AND/OR-разметка и эталонные пакеты. Эти данные не входят в поставку и не передаются агенту.
- `reports/` — первичные результаты, включая неудачные промежуточные проверки. `verification/reproducibility_evidence/` сохраняет хеши обеих чистых сборок; лишние копии исходников и промежуточных баз удалены.

Выполняемая часть использует стандартную библиотеку Python. Она не загружает документы, модели, веса или дополнительные пакеты. PyYAML используется только сборщиком; проверочные сценарии используют точные зависимости организаторов.

## Быстрая проверка исходного модуля

Из корня проекта:

```python
from pathlib import Path
from ml_knowledge import ReferenceArgs, ReferenceStore, canonical

with ReferenceStore(Path("ml_knowledge/corpus")) as references:
    response = references.get_reference(ReferenceArgs(
        mode="api",
        query="sklearn.neural_network.MLPClassifier.fit",
        library="scikit-learn",
        version="1.5.2",
        max_chars=6000,
    ))
    print(canonical(response))
```

Старые ID принимаются как адресуемые псевдонимы. Дедупликация может вернуть канонический ID общего документа; исходный запрос остаётся допустимым. Имя инструмента `get_reference` и режимы `search`, `api`, `read`, `methods`, `recipes`, `search_space` сохранены. Ответы имеют новый явный контракт `entry`/`entries`, тип материала, версию, источник, хеш документа, адресуемый фрагмент и статус применимости. Старый контроллер нужно адаптировать к этому контракту.

`max_chars` ограничивает весь результат `canonical(response)`: это число Unicode code points, включая JSON-метаданные и курсор. Байты UTF-8 и токены считаются отдельно. При переносе проверки в JavaScript следует учитывать различие с длиной строки в UTF-16. Токены знает только фактический транспорт/провайдер; модуль не выдаёт оценку по символам за измерение.

Продолжение чтения:

```python
with ReferenceStore(Path("ml_knowledge/corpus")) as references:
    args = dict(mode="read", reference_id="api_sklearn_impute_IterativeImputer", max_chars=6000)
    first = references.get_reference(args)
    if first.get("next_cursor"):
        second = references.get_reference({**args, "cursor": first["next_cursor"]})
```

Курсор передаётся при прежних запросе, режиме, ID и фильтрах. `limit` и `max_chars` менять можно. Начальный курсор — `None` или прежнее `0`; положительное число возвращает `invalid_cursor`. Изменение корпуса, ранжирования или переданного контекста применимости возвращает `stale_cursor`. В контекст курсора следует передавать стабильные отпечатки, а не постоянно меняющиеся счётчики времени.

Различаются `not_found`, `missing_version`, `ambiguous_symbol`, `budget_too_small`, `partial`, `invalid_cursor`, `stale_cursor`, `integrity_error`. `budget_too_small.min_chars` сообщает необходимый минимум. Отсутствие документа не означает отсутствия API в библиотеке.

## Подключение к сжимателю и контроллеру

1. Передавать `SelectionContext` только после подтверждения постановки. `fit_profile` содержит разрешённые агрегаты обучающей части; контрольные и скрытые метки в подборе не участвуют. `resources` описывает лимиты, а абсолютный дедлайн передаётся отдельно в `select(..., deadline=..., reserve_seconds=...)`. Он не обнуляется при перезапуске.
2. Подключить `ReferenceArgs`/`REFERENCE_SCHEMA`, включая строковый курсор. Передавать отпечаток реестра возможностей и схемы валидации при оценке применимости. Документация PyTorch или LightAutoML не включает адаптер и не подтверждает fit.
3. Хранить память в отдельном файле задачи, например `workdir / "knowledge_memory.sqlite"`. Не использовать существующий журнал агента без отдельной миграции таблиц и транзакций.
4. Формировать пакет через `select` или `pack`. Память расходует те же три места и 6000 символов. Существенные предупреждения и условия сохраняются целиком; непомещающийся материал обозначается как требующий дочитывания.
5. Перед отправкой вызвать `prepare_request(..., compressor=...)` либо `audit_request(actual_request, packet)` **после последней обработки контекста**. При потере блока отправка через этот интерфейс отклоняется. Сжиматель может оставить ограниченный блок целиком или контроллер может восстановить его и повторить проверку.
6. Проверять допустимость исполнения отдельно. `answer_usable=true` означает сохранность известных условий выбранных материалов. Это не доказательство полноты ответа, применимости метода или улучшения метрики. `applicability=unknown` сохраняется независимо от этого флага.
7. Раздельно регистрировать предоставление, ссылку и применение/отклонение. `KnowledgeMemory.outcome` требует проверку со стороны контроллера; ID в рассуждении не считается исполнением.

Минимальный пример подготовки запроса:

```python
from ml_knowledge import SelectionContext, select, prepare_request

context = SelectionContext(
    confirmed_task="classification",
    fit_profile={"missing": True, "categorical": True, "rows": 5000},
    validation="temporal",
    pipeline="OneHotEncoder LogisticRegression",
    resources={"cpu": 1, "memory_mb": 2048},
    capabilities={"lightautoml": False},
    fingerprints={
        "data_version": "data-v1", "task_hash": "confirmed-task",
        "feature_roles": "roles-v1", "validation_hash": "temporal-v1",
        "environment": "organizer-env", "pipeline_hash": "pipeline-v1",
    },
)
packet = select(references, context)
request, audit = prepare_request(
    [{"role": "user", "content": "Выбери следующий допустимый эксперимент."}],
    packet,
    model="configured-by-host",
    compressor=your_compressor,
    audit_path="actual_request_audit.json",
)
# Здесь существующий транспорт контроллера отправляет request.
```

Пример предполагает открытый `ReferenceStore` и переданную функцию `your_compressor`; он не запускает Qwen. Аудит может содержать пользовательские сообщения, поэтому его хранение и очистка относятся к политике журналов контроллера.

Для рекомендаций, гипотез и результатов нужны явные зависимости: `data_version`, `task_hash`, `feature_roles`, `validation_hash`, `environment`, `pipeline_hash`. Изменение зависимости помечает запись `stale_context`; изменение источника/версии — `stale_source`. История сохраняется. Противоречия отображаются в активном пакете и требуют проверки. Изменение поддерживающего источника делает рекомендацию устаревшей. Точное совпадение цитаты без обязательного предупреждения подтверждает происхождение, но не достаточность пакета. API-факт не теряет проверенное происхождение только из-за изменения пайплайна. Проверка цитаты подтверждает именно цитату; добавленные контроллером условия не превращаются автоматически в факт документации.

## Плоская поставка

После распаковки `releases/ml_knowledge_v003.zip` рядом находятся только корневые `.py` и неизменённый `requirements.txt`:

```python
import ml_knowledge_bundle
from mlkb_runtime import ReferenceArgs

with ml_knowledge_bundle.open_store(parent=workdir / "knowledge_runtime") as references:
    result = references.get_reference(ReferenceArgs(mode="api", query="torch.no_grad"))
```

Восстановление идёт порциями, проверяет размеры и хеши, затем публикует каталог атомарно. Тексты читаются лениво; весь корпус не удерживается в памяти. Корпус включает сторонние лицензии. Потерянный или повреждённый файл приводит к явной ошибке целостности.

Архив занимает **94 514 129 байта**. До общего лимита 100 000 000 байт остаётся **5 485 871 байт**. Сборщик объединённого решения должен включить этот корпус один раз и заново проверить размер, состав, холодный запуск и SHA-256 полной поставки. Нельзя переносить приёмку блока на новый архив решения автоматически.

## Воспроизведение проверок

```sh
python -m unittest discover -s ml_knowledge/tests -v
python -m ml_knowledge.build freeze
python -m ml_knowledge.build build --destination ml_knowledge/builds/new_clean
python -m ml_knowledge.benchmark --corpus ml_knowledge/corpus --output ml_knowledge/reports/local_resources.json
```

Сборка требует новый выходной каталог и проверяет хеши замороженных входов. Для достоверного сравнения нормализации нужно повторять `freeze` и `build` в двух независимых копиях закреплённых `sources`, `catalogs`, `baseline`, манифеста и файлов сборщика, с отключённой сетью. В приёмке использовались Linux, Python 3.12.15, SQLite 3.46.1 и точные зависимости организаторов. Побайтовая идентичность между разными версиями SQLite не обещается.

Отложенный набор уже раскрыт один раз. Его последующие запуски служат регрессиями, а не новым независимым подтверждением. Прежние версии разметки и неудачные разработочные отчёты сохранены. Разметка выполнена с помощью программы по точным участкам источников; независимая содержательная проверка человеком не заявляется.

Для живой приёмки после интеграции нужны шесть сценариев из плана, по два повтора старого и нового вариантов, всего 24 запуска. Оба варианта должны использовать одну замороженную архитектуру, одинаковые данные и протокол, seed 42, не более шести решений и 180 секунд от запуска доставленного `solution.py`. До серии следует измерить резерв ответов Qwen и подтвердить рабочие последовательности. Перед и после фактической серии обязателен `alpha-api-limits`. В этой работе реальный API не вызывался.

Изолированный стенд для конкретной версии подготавливается отдельно:

```sh
python ml_knowledge/tools/prepare_verification.py --release ml_knowledge/releases/ml_knowledge_v003.zip --destination /tmp/mlkb-check-new
```

Выходной каталог должен быть новым. В Linux-контейнер нужно смонтировать только `flat/` как `/case`, `harness/` как `/harness` (только чтение) и пустой каталог результатов как `/results`; запустить `python /harness/run_checks.py` из `/case`. Параметры приёмки: точные зависимости организаторов, сеть отключена, один CPU с affinity `[0]`, 2 ГиБ памяти, по одному потоку BLAS/OpenMP, `PYTHONDONTWRITEBYTECODE=1`. Стенд проверяет код именно из плоского архива; исходный проект не монтируется. Полный результат, включая вспомогательную неуспешную проверку исторических пакетов, сохраняется в JSON.
