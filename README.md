## Запуск

Нужны Python 3.12 и зависимости из неизменного файла организаторов `requirements.txt`. Среда соревнования должна предоставлять их заранее: агент не устанавливает пакеты и не скачивает модели во время работы.

Runner передаёт `OPENAI_API_KEY` и `OPENAI_BASE_URL`. `OPENAI_MODEL` необязателен: если он отсутствует или пуст, используется `qwen/qwen3.8-27b`; прокси организаторов выбирает модель задачи. Используется совместимый Chat Completions API с native tool calling и резервным JSON-транспортом. Локально можно заполнить `.env` по образцу `.env.example`; значения runner имеют приоритет. Ключ хранится только в локальном окружении, не в исходниках и архиве.

Локально настроен прокси организаторов и модель `qwen/qwen3.8-27b` по выданной инструкции. Адрес и ключ находятся в `.env`; платформа подставляет свои значения через окружение. Агент ограничивает контекст 262144 токенами. Параметры маршрутизации временного подключения удалены.

```sh
python solution.py /путь/к/task.md
```

Без аргумента используется `task.md` из текущего каталога. Первый допустимый CSV создаётся сразу после подтверждения постановки; затем его заменяют проверенные обученные результаты. При неоднозначной постановке модель возвращает структурированное предложение или `unresolved`. Неподтверждённый контракт не порождает предположительный CSV.

Для короткой локальной проверки:

```sh
python solution.py /путь/к/task.md --time-limit 180 --cpu 4 --memory-mb 10000
```

`--no-llm` выполняет опорный пайплайн и финализацию без исследовательских решений модели. `--transport json` позволяет проверить резервный транспорт. Лимит контекста по умолчанию — 262144; запрос ограничивается консервативной оценкой по байтам UTF-8, а фактические токены учитываются по ответам API. Параметры подключения, модель и дополнительные параметры запроса меняются через окружение без правок Python. При смене API надо обновить не только ключ, но и адрес, идентификатор модели и при необходимости `OPENAI_EXTRA_BODY`.

## Что реализовано

- Девять типизированных инструментов: `inspect_dataset`, `get_reference`, `train_model`, `run_automl`, `tune_model`, `analyze_experiments`, `build_ensemble`, `run_custom_experiment`, `finish`. `run_automl` поддерживает FLAML и AutoGluon, `tune_model` использует Optuna.
- Линейные модели, леса, бустинги, MLP, сплайны; числовые, категориальные и текстовые признаки; TF-IDF и hashing без внешних весов. Доступны регрессия, классификация, multioutput, multilabel, панельный прогноз и ранжирование.
- Медианная, нативная, KNN и итеративная модельная импутация с индикаторами пропусков, сохранением пустых столбцов и ограничениями значений. При числовых пропусках агент должен проверить модельное заполнение либо записать основание для пропуска.
- Независимые fit, внешняя validation и закрытый контроль. Временные периоды и группы сохраняются во внутренних split. Преобразования, HPO, ранняя остановка, калибровка и пороги обучаются внутри fit.
- Внешние диагностические отчёты регистрируются до оценки: периоды, блоки целых групп и диапазоны признаков с границами из fit. Малые и взаимодополняющие срезы скрываются; отдельные запросы ranking не раскрываются.
- Собственные пайплайны, преобразователи и анализ fit. Сохраняются исходный код, хеш и зависимости. Анализ возвращает типизированные скалярные агрегаты; малые агрегаты не уходят в API.
- Сопоставление предсказаний по неизменным внутренним ключам строк, явная карта классов вероятностей, проверка формы, конечности значений и порядка CSV. Пользовательские идентификаторы сохраняются, включая ведущие нули.
- Необратимое завершение поиска, фиксированные финалисты, однократный контроль, полный refit без нового HPO. CSV контрольного победителя публикуется до refit; при сбое остаётся пригодный результат.
- Журнал SQLite, идентичность операций, восстановление публикации, сохранение дедлайна и счётчиков. Неизвестный исход обучения не запускается повторно вслепую.
- Индекс прочитанных и недоступных источников сохраняется после другого инструмента, сокращения контекста и рестарта. Однозначное короткое имя API разрешается внутри закреплённой версии; неоднозначный символ возвращает варианты.

По умолчанию каждый запуск использует общий срок до 175 минут с запасом до внешнего трёхчасового лимита, до семи CPU и одно обучение одновременно. Отдельного 20-минутного лимита Qwen и ограничений в 12 кандидатов или 32 обращения нет. `--max-candidates` и `--max-calls` задают только явные ограничения для разработки. Два задания платформа запускает независимо; решение не делит срок одного задания пополам.

Резерв финализации определяется измеренной стоимостью финалистов; его минимальное значение для полного запуска — пять минут. В длительных запусках `finish` откладывается до этого окна. Временные ошибки API не замораживают поиск после трёх попыток: агент продолжает восстановление и может проверить другую поддерживаемую модель. При обрезании ответа увеличивается доступный размер следующего ответа. Неисправимые ошибки доступа или бюджета API отражаются в причине завершения после резервных экспериментов. Итоговый CSV имеет права 0644; внутренние файлы сохраняют прежние закрытые права.

Реальный предел памяти уменьшается с учётом доступной физической памяти и cgroup. Внешний монитор останавливает процесс при превышении времени, памяти, размера журнала или дефиците места. Допустимые HTTP/HTTPS-адреса модели берутся из окружения runner.

## Артефакты и восстановление

В каталоге задачи появляются `submission.csv` и `.agent_work/<run_id>/`. В последнем находятся подтверждённый контракт, разбиения, журнал, код, результаты обучения, предсказания, происхождение CSV и `run_report.json`.

По умолчанию `run_id` определяется хешем входных файлов. Повтор команды с теми же данными восстанавливает прежний запуск, сохраняя исходный дедлайн; завершённый поиск не открывается заново. Для отдельного эксперимента используйте новый `--run-id`. Исходные CSV не изменяются.

Рабочие артефакты могут содержать исходные данные и модели. Их не следует переносить в архив решения или передавать целиком в API. Ключ не попадает в окружение worker; ему передаются только разрешённые обучающие строки и признаки для предсказания.

Версии 16 библиотек, лицензии и хеши закреплены в `knowledge.lock.json`. Поиск использует SQLite FTS5 либо резервный лексический индекс. Осталось 400 неразрешённых включений документации; полнота не установлена. Справка не даёт разрешения на дополнительные зависимости, загрузки или исполнение неподдерживаемого адаптера.

`automl_agent/knowledge.py` соединяет справочник с контроллером. `get_reference` возвращает `entry`/`entries`, происхождение, условия, предупреждения и строковый `next_cursor`. Память каждой задачи хранится в `.agent_work/<run_id>/knowledge_memory.sqlite`, отдельно от журнала контроллера. Проверенный результат и его наблюдение по-прежнему сохраняются атомарно в основном журнале; память знаний восстанавливается как идемпотентная проекция. Ссылка в гипотезе не объявляется применённым методом. Прежний `knowledge_runtime/` сохранён для исторических инструментов разработки и в поставку v019 не входит.

Новый корпус собирает `ml_knowledge.build` из закреплённых входов `frozen/`; сборщик не импортируется при запуске агента. Исторический `tools/build_knowledge.py` обслуживает прежний корпус. Рецепт становится проверенным для конкретного режима только после реального fit/predict/save/load; наличие документации не подтверждает API исполнением. Необязательный адаптер LightAutoML остаётся отключённым до отдельной проверки.

## Проверка

`tests/` содержит технические проверки контрактов, метрик, границ данных, восстановления, библиотек, собственного кода, ансамблей и финализации. Локальная среда разработки содержит подмножество пакетов и не заменяет проверку точной среды.

`Dockerfile.full` создаёт отдельную проверочную среду Python 3.12 со всеми 37 прямыми зависимостями организаторов, без добавления pytest. `tools/offline_acceptance.py` проверяет 12 путей обучения, сохранение и повторное обучение при отключённой сети. Это воспроизведение зависимостей, а не официальный образ платформы.

`tools/live_acceptance.py` запускает девять сценариев по три повтора с настоящими решениями модели и объявленными техническими сбоями. История отказов сохраняется; константный CSV не считается обученным результатом. `tools/benchmark.py` сравнивает готовые подходы и агента на выданных данных при одинаковом общем бюджете и seed обучения 17, 42, 73.

Завершённые сравнительные прогоны могут хранить тяжёлые модели и предсказания в `execution_artifacts.zip`. Перед удалением несжатых копий проверяется SHA-256 каждого файла. Журналы, отчёты и опубликованные CSV остаются открытыми. Для восстановления используйте `python tools/archive_development_runs.py --restore <каталог_прогона>`.

Конкретные результаты и ограничения собраны в `IMPLEMENTATION_STATUS.md`. Технические фикстуры подтверждают исполнение расширенных семейств, но не их качество на неизвестных данных. Собственный Python работает в режиме ограниченного доверия: проверки импортов и I/O не являются изоляцией от намеренно враждебных нативных расширений. Локальная проверка не подтверждает результат на закрытых заданиях платформы.

## Архив для платформы

По инструкции организаторов от 20.10.2026 ZIP должен быть плоским и содержать только корневые `.py` и неизменённый `requirements.txt`, размером до 100 МБ. Текущая сборка содержит 224 корневых файла: `solution.py`, `agent_bundle.py`, `requirements.txt`, `ml_knowledge_bundle.py`, исходные модули `mlkb_*.py` и части справочника `mlkb_data_*.py`. Собственный код восстанавливается из `agent_bundle.py`, корпус — порциями из отдельных частей с проверкой размеров и хешей. Корпус включён один раз; сторонние пакеты, веса, обучающие данные и ключи в архив не входят.

`tools/build_flat_submission.py` создаёт отдельный каталог сборки и сверяет исходники модуля с неизменяемым выпуском `ml_knowledge_v003.zip`. Нумерованные архивы, статический manifest и отдельное свидетельство фактической проверки находятся в `dist/`. Текущая версия — v019; её состав и ограничения записаны в `dist/solution_v019.acceptance.json`. `dist/LATEST.json` и `dist/CANDIDATE.json` указывают на этот архив с явно неполной приёмкой исходного плана качества. Предыдущие версии и свидетельства сохранены. Загрузка на платформу автоматически не выполняется.
