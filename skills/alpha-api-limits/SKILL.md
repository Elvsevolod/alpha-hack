# Лимиты API «Альфа»

Используй [scripts/check_limits.py](scripts/check_limits.py) для запроса
`GET https://changellenge.up.railway.app/key/info` с `Authorization: Bearer`.
Скрипт выполняет команду организаторов через curl, передавая заголовок через stdin.

## До и после прогонов

1. До каждого тестового прогона или серии, обращающейся к реальному API
   организаторов, проверь лимиты и сохрани снимок `before` в новом каталоге
   результатов этого прогона. К этому относятся smoke-тесты, live acceptance,
   бенчмарки и пробные вызовы Qwen. При фоновой работе дождись фактического
   завершения процесса перед проверкой `after`.
2. Сообщи пользователю остаток и общий лимит. При `blocked=true` или
   `budget_exhausted=true` не начинай новый live-прогон. При ошибке запроса
   сообщи, что остаток неизвестен; не выдавай старый снимок за текущий.
3. После завершения, ошибки или отмены прогона повтори запрос, сохрани `after`
   рядом с `before` и укажи изменение счётчика расхода. Если начального снимка
   нет, всё равно проверь текущий остаток, но расход прогона не вычисляй.
4. Заверши коротким сообщением: остаток до → после, изменение расхода и
   обнаруженные ограничения. Если запрос после прогона не удался, явно укажи,
   что итоговый остаток не подтверждён.

Выполняй команды из корня проекта, используя его `.venv/bin/python` с уже
установленным `python-dotenv`. Путь к скрипту разрешай относительно этого
`SKILL.md`. Ниже показана копия скилла в проекте; при установленном скилле
подставь путь его собственного `scripts/check_limits.py`.

```bash
.venv/bin/python skills/alpha-api-limits/scripts/check_limits.py before --output outputs/ИМЯ_НОВОГО_ПРОГОНА/api_limits_before.json
```

Затем выполни запланированный прогон и независимо от его кода завершения:

```bash
.venv/bin/python skills/alpha-api-limits/scripts/check_limits.py after --before outputs/ИМЯ_НОВОГО_ПРОГОНА/api_limits_before.json --output outputs/ИМЯ_НОВОГО_ПРОГОНА/api_limits_after.json
```

Для разовой проверки:

```bash
.venv/bin/python skills/alpha-api-limits/scripts/check_limits.py status
```

Снимки не перезаписываются: для нового прогона выбирай новый каталог.
Код завершения `0` означает успешную проверку, `2` — ошибку проверки,
`3` — полученный ответ с исчерпанным бюджетом или блокировкой.

## Ключ и трактовка ответа

- Ключ берётся из `OPENAI_API_KEY` окружения, а при отсутствии переменной —
  из локального `.env` (`--env-file` задаёт другой файл). Это должен быть
  тот же ключ, с которым запускается тест. Не передавай ключ аргументом
  командной строки и не выводи `.env`, заголовки или полный ответ API.
- Ответ API содержит сам ключ. Скрипт сохраняет только разрешённые поля
  лимитов, время и короткий SHA-256 отпечаток для проверки совпадения ключей.
- Остаток бюджета: `info.max_budget - info.spend`. `total_spend` — отдельный
  общий счётчик; не вычитай его из лимита текущего периода. Отсутствующее
  значение или `null` означает неизвестное/неуказанное ограничение, а не ноль
  и не подтверждённый неограниченный доступ. Не называй единицы бюджета
  токенами или долларами без подтверждения организаторов.
- Сравнение использует `total_spend`, а при его отсутствии — `spend` только
  при совпадающей известной дате сброса. При смене ключа, сбросе счётчика или
  отсутствии данных расход не вычисляется. Изменение относится к интервалу
  между проверками и может включать другие процессы с тем же ключом;
  мгновенное обновление счётчиков сервером не гарантируется.
- `rpm_limit`, `tpm_limit`, `tpd_limit` и `max_parallel_requests` — заданные
  ограничения скорости/параллельности, а не остаток запросов или токенов.
- Это локальная проверка разработки. Не добавляй её в `solution.py`,
  runtime агента или архив сабмита; она не запускает тесты и обучение сама.
