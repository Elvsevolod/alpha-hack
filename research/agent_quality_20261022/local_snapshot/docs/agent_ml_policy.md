# Проект методической инструкции для ML-агента

Дата: 22.10.2026. **Статус: подготовлено, не включено в действующий SYSTEM и ZIP.** Это предлагаемая часть доверенной системной политики, а не инструкция, которую нужно разрешить выполнять произвольной справочной странице. При интеграции сохранить действующие контракты приватности, инструментов, времени и финализации.

## Компактный текст для подключения

Перед выбором метода установи основную метрику, тип выхода, единицу наблюдения, момент доступности признаков и объект переноса. Различай новые строки, новые объекты, будущие периоды и новые группы в будущем. Не меняй подтверждённую постановку. Совместные ограничения времени и групп нельзя заменить одним удобным случайным split; неподдержанный протокол обозначай явно.

После технически корректной опоры выбери следующую гипотезу по наибольшему подтверждённому риску: неверный перенос, утечка/дубли, редкие классы, тяжёлый хвост, пропуски, представление, сложность модели. Не назначай один метод обязательным для всех датасетов. Для каждой попытки укажи наблюдение, альтернативное объяснение, одно основное изменение, ожидаемый эффект на целевую метрику, приёмку и стоимость.

При дисбалансе проверяй покрытие классов и точный macro/micro/weighted режим. Сравни невзвешенную опору с ограниченной гипотезой весов; веса и oversampling не гарантируют роста F1. Полноценные per-class precision/recall/F1 оценивай на всей внутренней оценочной части fit, используя OOF либо отдельный внутренний holdout. Метрика на строках одного истинного класса не является его обычным F1. Малый support означает неопределённость. Подавленные внешние срезы не восстанавливай.

Различай бинарный порог, калибровку вероятностей и многоклассовое правило решения. Встроенная постобработка текущего адаптера бинарная; многоклассовый вариант требует проверенного custom-пути. Любые обучаемые пороги, смещения классов и веса ансамбля подбирай внутри fit. Для Log Loss сохраняй вероятности и порядок классов; не превращай их в метки.

При регрессии анализируй ошибки в исходной шкале. Log-target, clipping, робастная функция потерь и перевзвешивание — отдельные гипотезы, а не обязательное лечение хвоста. Для RMSE крупные правдоподобные значения важны; удаление хвоста может ухудшить результат. После log-преобразования обратный exp не обязан давать условное среднее исходного таргета. Исправление смещения обучай только внутри fit.

При пропусках сравни нативные NaN, простую импутацию с индикаторами и модельную импутацию по наблюдениям и бюджету. Проверь изменение доступности признаков между периодами и незнакомыми группами. Не утверждай механизм MNAR по одной таблице. Не смешивай числовые NaN, пустые категории и семантические строки вроде «нет сервиса». Сохраняй фиксированную схему, включая пустые столбцы.

Проверяй точные/близкие дубли и противоречивые метки без использования ID как признака. Дубли не всегда надо удалять; они меняют эффективный размер данных и могут делать случайную оценку оптимистичной. Пересечение ID разных файлов не разрешает переносить метки. Неизвестные категории должны иметь определённое поведение. Target encoding требует cross-fitting с сохранением нужных временных и групповых границ; возможности текущей версии проверяй до вызова.

Отличай сдвиг признаков от сдвига долей классов и изменения p(y|x). По тестовым признакам нельзя установить произвольный concept drift. Неразмеченный тест разрешён для диагностических агрегатов по контракту, но не для обучения преобразований, весов, псевдометок или адаптации модели при действующем fit-only правиле.

Используй точные версии разрешённых библиотек и реестр возможностей адаптера. Результат поиска, цитата API и исполнимая совместимость — разные свидетельства. Готовый путь предпочтителен для стандартного метода; custom-компонент нужен для проверяемой новой гипотезы. Таймаут характеризует стоимость, не качество семейства.

Сравнивай перспективные альтернативы при одном внешнем протоколе; подробный выбор параметров и проверку устойчивости выполняй внутри fit. Многократные попытки могут переобучить отбор по validation. Технический min_delta не является статистической достоверностью. Закрытый control использует только контроллер после заморозки.

Считай стоимость всего графа: преобразования, вспомогательные fit, внутренние folds, HPO, прогноз, сохранение, контроль и полный refit. Сначала ограниченный пилот стоимости, затем содержательная проверка. Сохраняй пригодный результат и измеренный резерв. При плато меняй обоснованную причину ошибки или представление; одинаковые чтения и повторение той же конфигурации не дают новых свидетельств.

## Что заменить в существующей инструкции

1. Заменить абзац, который требует при числовых пропусках приоритетно запускать `iterative_bayesian_ridge`, на абзац о сравнении нативной, простой и модельной обработки по наблюдаемой проблеме.
2. Добавить пояснение, что классовый срез текущего внешнего отчёта не заменяет полный per-class F1.
3. Добавить границу бинарной и многоклассовой постобработки.
4. Сохранить существующие ограничения fit-only, control, внешних масок, неизменности метрик и источников.
5. Развёрнутые сценарии держать в поисковой базе, а в SYSTEM — только правила выбора. Перед включением измерить размер фактического запроса и проверить все уровни сжатия.

## Маршрутизация знаний

В вопрос поиска включать подтверждённую метрику, схему переноса, симптом и цель текущей гипотезы. Примеры **смысловых запросов**, а не готовых аргументов неизвестного API:

| Наблюдение | Вопрос к справочнику |
|---|---|
| Macro F1, редкий класс, дубли | rare classes; group duplicates; precision recall tradeoff; fit-only diagnostics |
| RMSE, тяжёлый хвост, log-target | original-scale squared error; inverse-transform bias; raw vs log ablation |
| Следующий год, пропуски меняются | temporal validation; missingness shift; native NaN vs indicators |
| Новый клиент в будущем | joint temporal group validation; inner boundary preservation |
| Плато качества | alternative representation; error mechanism; limited tuning; ensemble compatibility |

Новые `case:MLxx` из JSON не являются текущими method/API ID. До штатной интеграции не передавать их в `method_refs`, `reference_ids` или `hypothesis.evidence_refs` действующего агента.
